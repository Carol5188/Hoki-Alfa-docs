## 1. 当前结论与口径裁决

**功能总开关与支持范围满足后，房主在有效白名单中，或房主财富等级达到统一门槛，任一满足即可开通。有效白名单直接开通，不再配置或展示该账号的财富门槛。房间有资格后，房主和本房管理员均可管理一起看。**

| 问题 | 历史v2.0 | 当前裁决与来源 |
|---|---|---|
| 准入关系 | 推荐白名单AND财富门槛 | 2026-10-28用户明确回复“可以：白名单或财富达标，任一满足即可”；改为OR，不再待确认 |
| 白名单弹窗 | 继承默认/自定义最低/不限等级 | 用户批注“已经添加了白名单了，不用展示门槛了”；白名单直接豁免财富条件，删除单账号门槛配置 |
| 列表字段与操作 | 当前财富、等级门槛、房间资格；编辑/启停 | 用户要求新增操作时间（添加白名单时间）、操作人；操作改移除。去掉表内等级门槛，保留原房主/当前财富/有效期/白名单状态/房间资格 |
| 移除确认 | 原停用需填原因 | 普通确认弹窗，取消/确认移除，无新增表单、无额外审批；审计自动记录移除人和时间 |

## 2. 准入规则

房间可用 = 总开关开启 ∧ 支持区服/语聊房型/客户端版本 ∧（当前房主有效白名单 ∨〔财富准入开启 ∧ 房主财富等级≥统一最低等级〕）。

| 条件 | 当前规则 |
|---|---|
| 有效白名单 | 绑定当前房主UID；在名单且未过期即可，无财富门槛、不再保存threshold_mode/custom_min_level |
| 财富通道 | 未在有效白名单也可按财富达标开通；关闭该通道后只接受有效白名单，并不全量开放 |
| 总开关/支持范围 | 两种通道都受其约束，白名单不能绕过功能停用/不支持房型/区服/版本 |
| 白名单期限 | 沿用长期有效或指定截止时间；服务端时间严格早于expires_at才有效，届满回退财富通道 |
| 移除/过期 | 仅撤销名单豁免，重算财富通道；仍达标继续可用，两条通道都不满足才失资格 |
| 操作时间 | 表格显示该次添加的created_at，不是最后更新时间；重新添加生成新记录与新的时间，历史移除审计保留 |
| 操作人 | 显示添加该记录的后台操作者昵称/账号ID，由登录身份确定，不允许运营手填冒用；移除人另记审计 |
| 财富来源 | 现有服务端财富等级，不读余额/魅力、不重算充值或成长、不新增钱包结算 |
| 管理员 | 有资格房间内按本房角色管理，无需个人名单或财富达标；管理员个人白名单不能为他人房间开通 |

示例默认Lv10：白名单Noura/Lv5直接开通；非白名单Farah/Lv20财富达标可用；Noura移除后Lv5不达标则失资格；Carol/Lv12移除后仍以财富资格可用。Lv10及1—999范围仍是演示参数，正式等级字典/门槛待业务确定。

## 3. 后台页面与操作路径

### 现有后台样式

按用户指定本机页面实际截图和DOM样式复用：224px黑侧栏，52px白顶栏，绿色主按钮、白底描边次按钮，页签绿底/绿下划线，筛选面板与表格分区，浅灰表头、灰色细边框、小圆角。弹窗为白底标准标题、右上角关闭、底部分隔线和右对齐按钮。小屏侧栏折成54px图标栏，表格内部横滚，操作列固定在右侧。

左侧“房间管理”一级菜单下设置“观看视频管理”入口，当前页面固定标题“观看视频管理”；页内仅“白名单 / 功能配置”两个Tab，默认白名单。面包屑为“房间管理 / 观看视频管理 / 当前Tab”。删除独立操作记录Tab、侧栏入口及页面。房间管理分组支持展开/收起，页内Tab不重复出现在左侧；截图中的同级菜单仅用于展示导航位置，不演示其业务跳转。后台是独立全页样式，房内继续原紫色语聊房。参考页面仅用于样式，未修改它或亲密关系业务数据。

### A. 白名单列表

- 查询条件：房主UID/昵称、添加操作人、白名单有效/过期状态、添加时间起止日期；查询/重置。日期展示原型统一UTC+8，正式接运营时区配置。
- 列表：房主（昵称/UID）、当前财富、有效期、白名单状态、房间资格、操作时间（添加白名单时间）、操作人、操作。
- 不展示单账号门槛；当前财富和房间资格保留作只读信息。操作仅“移除”；无编辑/启用/停用。列表默认添加时间倒序，支持分页/页大小和空结果。

### B. 添加白名单

1. 点击“添加白名单”，输入UID，查询显示昵称确认对象；不展示或填写财富门槛。
2. 沿用有效期和添加原因；指定截止时间须有效且晚于服务端当前时间。
3. 点击“确认添加”；未知/非法UID、重复记录、非法有效期、缺少原因在弹窗内提示并保留输入。重复项不覆盖旧created_at/created_by；已过期但仍留列表的记录需先移除再添加。
4. 成功后新记录带服务端created_at和登录操作者created_by，自动刷新列表；可返回房内验证。失败不写记录不改资格，允许重试。

### C. 移除白名单

点击行内“移除”→普通确认弹窗“移除白名单？”→显示昵称/UID及“移除后将按房主财富等级重新判断功能资格”→取消/确认移除。无需输入原因或再次提交配置。

取消、关闭、Esc均不改变记录。确认成功后从当前列表移除，保留历史审计；失去豁免后按财富通道重算。仍满足财富条件则继续观看；不满足时按推荐策略结束本场、语聊继续。失败保留记录与会话并允许重试。已被其他运营移除时返回最新状态，重复请求幂等，不重复写审计。

### D. 功能配置（准入配置）

配置页提供总开关、财富等级准入开关、统一最低财富等级与变更原因。关闭财富准入保留已保存等级值；有效白名单不受等级调整影响。保存前普通确认说明影响；成功发布新版本重算，失败保留旧配置。本模块不设置独立操作记录页面。原有服务端变更留痕按平台通用审计机制保留；白名单列表中的添加时间和添加人照常展示，不增加本模块查询入口。

| 对象 | 最小字段 |
|---|---|
| 统一规则 | enabled、wealth_gate_enabled、min_wealth_level、region/channel/client范围、room_type=voice、version、reason、updated_by/at |
| 白名单记录 | id、owner_uid、expires_at（可空）、reason、created_at、created_by_id/name、row_version；移除保留removed_at/by审计 |
| 资格快照 | room_id、owner_uid、eligible、source=whitelist/wealth/none、deny_reason、owner_wealth_level、policy_version、evaluated_at |
| 审计 | 操作ID、操作者/角色、对象、动作、前后值、原因、服务端时间、配置版本、影响范围及结果 |

正式后台由已有RBAC控制新增/移除/配置发布；只读角色查询。操作者与时间由服务端写入，UTC存储/运营时区展示；原型添加时间按当前时刻、UTC+8展示，初始两条为固定假数据。保存带预期版本和操作ID，服务端串行、幂等及冲突保护。

原型10001 Carol/Lv12、10002 Noura/Lv5、10003 Farah/Lv20均为演示账号；后台、审计和房内同步仅当前页内存，刷新还原，不接真实后台或跨标签同步。

## 4. 房间角色与入口

| 能力 | 房主 | 本房管理员 | 普通成员 | 有后台权限的运营 |
|---|---|---|---|---|
| 符合资格时看到一起看工具入口 | 是 | 是 | 否 | 不代替房内角色 |
| 预览链接、发起、换片 | 是 | 是 | 否 | 不代替用户发起 |
| 改共享播放/暂停/进度、重播 | 是 | 是 | 否 | 可运营终止 |
| 结束全房会话 | 是 | 是 | 否 | 可按处置权限终止 |
| 加入观看、音量、静音、放大、收起 | 是 | 是 | 是 | 不控制成员个人音量 |
| 配准入规则/房主白名单 | 否 | 否 | 否 | 按后台RBAC |

房间不具备资格时，房主与管理员均隐藏一起看入口；普通成员不出现无法使用的活动卡。显示隐藏只影响新功能，不影响现有语聊、公屏、礼物或游戏规则。后台显示明确拒绝原因；客户端提交时权限变化给可解释提示，不暴露内部名单与审核因子。

普通成员的官方YouTube播放器控件必须保留，其本机暂停/跳转不广播为Hoki共享命令。支持在播放器外点击「跟上当前进度」恢复，不能用遮罩强封官方控件。

## 5. 用户完整路径

1. **运营开通**：添加房主UID→核对昵称→设置有效期/原因→确认添加；或配置统一财富门槛。房间按两种通道任一满足生成资格。
2. **管理者发起**：符合资格房间的房主或管理员→底部房间工具→YouTube一起看→粘贴单视频链接→预览→确认开始。
3. **成员加入**：全房活动卡显示邀请→成员主动点击加入→必要时点击播放解锁本机播放器→跟随当前共享时间，继续语聊。不强制有声自动播放。
4. **共同观看**：房主/管理员均可全房暂停、继续或释放进度条后提交跳转；个人音量/静音/麦克风/放大/收起各自独立。
5. **管理者换片**：菜单或工具→更换视频→预览→确认。预览期间旧片保留，失败不影响旧片；成功原子切换、进度归零。已收起成员不被强制打开；静音和麦克风选择保留。
6. **管理者结束**：房主或管理员点结束→二次确认→全房结束视频，仍在语聊房。普通成员收起只停本机媒体，不结束会话。
7. **晚加入/返回**：读当前资格和会话快照，主动加入后跟随当前位置；暂停会话保持暂停；已结束不重开旧播放器。

只提交链接，不上传视频文件，不采集房主屏幕转播。每个人分别加载官方播放器，Hoki同步内容ID与共享状态。本期仍推荐仅语聊房单点播，不做搜索、播放队列、成员点播、直播/Shorts或后台听歌。

## 6. 资格/角色变化与管理者离线

| 变化 | 推荐处理 |
|---|---|
| 白名单移除/过期 | 撤销豁免并按财富通道重新判断；财富仍达标则继续，两条均不满足才结束并隐藏入口 |
| 总开关关闭/财富不达标 | 总开关关闭两条通道都失效；财富降低仅影响没有有效白名单的房间；失资格按推荐策略结束视频，语聊继续 |
| 提高统一财富门槛 | 有效白名单不受影响；其他账号按新门槛重算，失资格才结束 |
| 降低门槛/财富升级/添加白名单 | 任一条件满足后显示入口，不自动发起或恢复旧会话 |
| 管理员被降权/移除 | 立即撤销该人的共享操作，关闭选片/结束弹窗、废弃旧预览；已加入观看可保留为普通成员。不因其个人降权撤销整房资格 |
| 管理员新增 | 有资格房间中入口即时可见；不自动加入或播放 |
| 管理员个人等级变化 | 不影响本房操作资格；判定使用房主等级 |
| 房主离房/断线，仍有其他房主/管理员在房在线 | 其他管理者继续操作，不再沿用“房主一离开全房结束” |
| 最后一名在线管理者离房/断线 | 共享暂停；推荐服务端确认后宽限30秒，任一有效管理者返回后保持暂停、主动继续；超时结束。主动离房先说明影响并确认 |
| 房主身份转移 | 推荐先结束当前会话，再按新房主资格显示入口；新房主/管理员主动重新发起 |
| 切游戏模式、解散房间或运营终止 | 按房间既有确认/通知结束会话，不把视频带进游戏层 |

即时收回、30秒和身份转移策略属于评审建议；正式发布前确认。服务端计算在线管理者集合，不能只看房主在线或只看当前发起人；管理员退出不会撤销他已发起的会话，只要还有其他管理者在线。

## 7. 并发、服务与数据

房间资格、房间角色、YouTube会话分三层，不把某个管理员个人白名单写入会话控制权。每次预览、发起、播放/暂停、seek、换片、结束均由服务端验证：账号在房、当前角色、房间资格、房型/地区/版本、会话与配置版本。仅隐藏按钮不构成权限校验。

原会话字段继续含room_id、session_id、media_version、video_id、duration、shared_state、position_anchor_ms、anchor_server_time_ms、revision。补充owner_uid、effective_policy_version、initiator_uid、last_command_actor_uid/role、end_reason、controllers_online_count。每条控制指令携带command_id、expected_revision、expected_media_version、expected_policy_version；服务端串行接受，返回新快照。

房主与多个管理员可同时操作，避免各端以本地状态各自获胜：后到的过期命令拒绝并刷新。共享跳转释放后提交一次；程序同步的播放器回调不再次发指令。预览绑定输入、角色、配置与会话版本；在其他管理者换片/结束后，旧预览不能覆盖新会话。原型用单页双角色模拟版本防护，真实多管理员并发待服务端验收。

播放目标 = min(duration, anchor + now_server − anchor_server_time)；暂停固定anchor。广告、缓冲、区域限制和自动播放被拦截独立处理，不跳广告、不让一位成员拖停全房、不承诺逐帧同步。个人恢复后取最新快照再纠偏。

推荐资格变更推送到受影响房间，按配置版本去重；推送丢失时，后续指令/进房/重连必须重新读取服务端结果。有效期按服务端定时及请求校验双重保障，不能依赖客户端本地时钟。白名单与门槛变更不新增钱包、工资、返奖或结算行为。

## 8. 沿用的观看交互与边界

- 保留紫色语聊房背景、麦位和底部工具，观看卡在麦位下方、公屏上方；公屏用紧凑紫色分类条，无游戏缩放按钮、居中箭头或绿色大遮罩。
- 官方播放器viewport至少200×200，保留官方控件/来源/广告；房间礼物横幅和动画不得盖在播放器上。原型画面、标题、时长和同步是假数据，不能当成官方最终UI。
- 普通成员邀请卡不依赖当前公屏Tab。公屏可点切Tab，真实手势仍遵循公屏切换v3.1；视频区手势归播放器，不触发房间横滑。
- 收起、播放器完全不可见、整屏公屏、后台/锁屏、切房时停止本机视频和声音，回来主动加入；共享会话按房间管理者状态继续或暂停。管理员后台配置评审面板是模拟另一个系统，不把切评审页面当作真实App生命周期。
- 视频音量与语聊/麦克风独立，不自动开麦；50%初始视频音量为推荐待评审。保留耳机建议；Android/iOS蓝牙、来电、音频焦点、外放回声需真机。
- 有BGM时推荐开始前提示，成功发起后暂停房间BGM；失败不暂停，结束后不擅自恢复。原型未接真实BGM。
- 支持普通youtube.com/watch与youtu.be短链接，严格白名单域名和合法video_id；首期不支持Shorts/直播/列表。实际类型、私密/删除/嵌入限制、年龄/地区等由官方服务验证，合法格式不保证播放。
- 官方播放器不用于隐藏后台听歌、抽音轨、下载转播、广告过滤、付费观看或观看激励。不收集YouTube账号密码、不绕过地区/年龄限制；正式接现有隐私告知、YouTube条款和Google隐私链接。
- 举报沿用现有房间体系，以会话与video_id关联，举报本身不自动结束；运营终止有审计。继承v1.0已经核对的YouTube官方要求。

## 9. 异常、埋点与发布

账号查无结果/重复白名单/统一门槛缺失/过期时间非法：弹窗内提示，保持输入；保存失败不改配置、不收回权限；版本冲突刷新后重新确认。准入未知/配置读取失败时不授权新的管理操作，不拿本地缓存永久授权，普通语聊继续。

播放器失败仅影响本机，发起/换片未确认成功不广播；提交失败取会话快照确认最终状态，避免超时重发创建两场。管理员降权后迟到回调失效，角色恢复不自动重发旧命令。

原有发起/加入/首帧/共享控制/本机控制/错误/结束埋点补actor_role、owner_uid、eligibility_reason、policy_version与end_reason。后台新增allowlist_create/remove、policy_update、eligibility_changed；记录变更结果与影响对象。不向分析埋点上传原始带追踪参数的链接。

内部测试→地区/版本小范围→扩大，观察发起/加入成功、权限拒绝、过期命令、配置生效延时、误收回和音频投诉。正式开关初始值由运营确认，原型开启不代表上线默认。回滚到上一配置版本也必须重算资格，不恢复已结束旧视频。紧急停用按本轮建议结束会话；若要“只停新发起、存量续播”，应另设独立发布策略，不复用本准入开关产生两种含义。
