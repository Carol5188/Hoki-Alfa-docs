# Hoki 语聊房 · YouTube 一起看

v2.0｜可评审版｜2026-10-23（Asia/Shanghai）  
本轮新增后台房主白名单、财富等级准入、房主与管理员共同管理。当前方案与综合HTML供评审，未接入真实后台、YouTube或房间服务，未发布、未归档。

## 1. 当前结论与口径裁决

**后台先给房主UID添加白名单，可同时配置财富等级门槛；该房主的房间满足条件后，房主和本房管理员都可发起、换片、控制共享播放及结束一起看。普通成员主动加入观看。**

“开通资格”与“操作权限”分开：资格跟当前房主账号走，操作权限跟本房角色走。管理员无需额外加入白名单或满足个人财富等级，但不能把自己在A房的管理能力带到B房。

| 问题 | v1.0旧口径 | 本轮新口径与来源 | 裁决 |
|---|---|---|---|
| 功能入口 | 仅房主 | 用户要求有功能的房间房主、管理员均可操作 | 入口及完整管理权限同时开放给房主/本房管理员，覆盖v1.0 |
| 房间资格 | 未定义账号准入，仅推荐灰度 | 用户新增后台白名单与房主财富等级门槛 | 白名单绑定房主UID，门槛同页配置；细则按下文推荐，待评审 |
| 管理员个人准入 | 无管理权 | 用户按“有这个功能的房间”授权房主和管理员 | 不再对管理员重复校验个人白名单/财富等级 |
| 房主离房/断线 | 房主离开即结束；断线暂停 | 允许管理员管理后，原建议不适配 | 推荐有其他管理者在线则继续；无人管理才暂停等待，超时结束 |
| 规则调整生效 | 未定义 | 本轮补充 | 推荐保存成功后重算；失去资格立即结束现有观看，后台事先提示影响；非用户已批准的上线策略 |

用户已明确白名单、财富等级关联与管理员操作；AND关系、账号豁免、有效期、立即收回、无人管理宽限等为本轮推荐规则。v1.0保留为历史，不与本文件并用判断权限。

## 2. 准入规则

推荐基础方式为“房主白名单必需，财富门槛可选”。默认不做“财富达标就自动开通所有房间”，以便运营控制首期范围。

房间可用 = 总开关开启 ∧ 支持区服/房型/客户端版本 ∧ 当前房主有效白名单 ∧ 房主财富等级达到有效门槛。

| 条件 | 含义 |
|---|---|
| 白名单对象 | 房主用户UID，不是房间ID、管理员UID或普通成员UID；同一UID作为房主的受支持房间均可按规则获得资格 |
| 记录有效 | 已启用，且长期有效或当前服务端时间严格早于截止时间；到截止时刻即失效 |
| 默认门槛 | 后台可开关“默认要求财富等级”；开启后从正式财富等级字典选择最低等级 |
| 账号门槛：继承默认 | 默认门槛开则使用默认等级，关则不限等级 |
| 账号门槛：单独设置 | 采用此UID的最低等级，不随统一默认调整；即使默认门槛关闭仍生效 |
| 账号门槛：不限等级 | 对该UID豁免财富门槛，仍须满足有效白名单、总开关、房型/地区/版本等条件 |
| 财富等级来源 | 读取平台现有、可信服务端财富等级，不使用余额/魅力等级，不在此模块重算充值或财富成长规则 |
| 管理员不达等级 | 只要房间有资格且其本房管理员身份有效，就可管理；管理员个人财富等级不参与此公式 |

例如，默认最低Lv10：白名单房主Lv12可开通；白名单房主Lv5暂未达标，可为其改为“单独Lv5”或“不限等级”；非白名单房主即使Lv20也不开通。Lv10/Lv5/Lv12/Lv20及原型1—999范围均为演示值，不是已批准的门槛或正式等级上限。

仅在他人房间作为成员或管理员的白名单用户，不使那个房间获得资格；切房、换房主时必须重新按所在房间当前房主判断。房主在线与否不改变资格归属。

## 3. 后台操作路径

### A. 配统一规则

1. 运营打开「YouTube 一起看 → 准入管理」。顶部显示配置版本，页面包括统一规则、房主白名单列表、操作审计。
2. 配置总开关、是否默认要求财富等级及默认最低等级。关闭默认门槛保留原值，方便重新开启；页面明确单独配置不受默认门槛影响。
3. 填写变更原因，点击保存；先展示变更前后规则、影响范围提示，以及会否使正在观看的房间失去资格。正式后台由服务端计算实际影响房间数，不用客户端猜测。
4. 确认保存成功后发布新版本并触发重新判断；失败保留原配置与当前会话，允许重试。取消或恢复已保存值不发布。

### B. 添加/编辑房主白名单

1. 点「添加房主白名单」；输入房主UID，查询确认昵称、当前财富等级，防止误加。账号不存在、UID非法或已存在时不创建；已存在引导编辑原记录。
2. 同一弹窗选择该房主的门槛：继承统一默认 / 单独最低等级 / 不限等级。选单独等级才展示必填等级字段。
3. 选择长期有效或指定截止时间，填写操作原因。指定时间必须有效且晚于当前服务端时间。
4. 确认后新增记录，自动计算“白名单记录状态”和“房间资格”，两列分开。有效白名单不等于必然已开通，财富未达标时保留记录，显示具体原因。
5. 编辑同一条记录即可调整门槛、有效期；停用保留记录和审计，可重新启用。重新启用也须重算有效期与门槛，不能绕过已过期或不达标。
6. 列表支持UID/昵称查询、有效/停用/过期筛选、空结果；表格在手机上内部横向滚动，不撑破页面。

原型提供10001 Carol/Lv12、10002 Noura/Lv5、10003 Farah/Lv20三组假账号，模拟查询与新增/编辑/启停/保存失败。刷新还原示例，不持久化或写入真实后台。

### 后台字段与权限

| 对象 | 最小字段 |
|---|---|
| 统一规则 | enabled、default_wealth_gate_enabled、default_min_wealth_level、region/channel/client白名单、room_type=voice、version、reason、updated_by/at |
| 房主白名单 | owner_uid、status、threshold_mode=inherit/custom/none、custom_min_level、expires_at（可空）、reason、created_by/at、updated_by/at、row_version |
| 房间资格快照 | room_id、owner_uid、owner_wealth_level、eligible、deny_reason、effective_min_level、policy_version、evaluated_at |
| 审计 | 操作人/角色、对象UID、动作、前后值、原因、服务端时间、配置版本、影响范围、成功/失败 |

仅具备配置权限的运营可新增、修改、启停和发布；只读角色可查询；客户端房主/管理员不能修改运营白名单。正式接现有后台RBAC与发布流程，不额外虚构审批层级。保存带预期版本，冲突返回新快照，不能覆盖其他运营刚保存的配置；重复请求按操作ID幂等。UTC保存时间、运营时区展示并显式标注；原型仅本机时区演示。

## 4. 房间角色与入口

| 能力 | 房主 | 本房管理员 | 普通成员 | 有后台权限的运营 |
|---|---|---|---|---|
| 符合资格时看到一起看工具入口 | 是 | 是 | 否 | 不代替房内角色 |
| 预览链接、发起、换片 | 是 | 是 | 否 | 不代替用户发起 |
| 改共享播放/暂停/进度、重播 | 是 | 是 | 否 | 可运营终止 |
| 结束全房会话 | 是 | 是 | 否 | 可按处置权限终止 |
| 加入观看、音量、静音、放大、收起 | 是 | 是 | 是 | 不控制成员个人音量 |
| 配准入规则/房主白名单 | 否 | 否 | 否 | 按后台RBAC |

房间不具备资格时，房主与管理员均隐藏一起看入口；普通成员不出现无法使用的活动卡。显示隐藏只影响新功能，不影响现有语聊、公屏、礼物或游戏规则。后台显示明确拒绝原因；客户端提交时权限变化给可解释提示，不暴露内部名单与审核因子。

普通成员的官方YouTube播放器控件必须保留，其本机暂停/跳转不广播为Hoki共享命令。支持在播放器外点击「跟上当前进度」恢复，不能用遮罩强封官方控件。

## 5. 用户完整路径

1. **运营开通**：添加房主UID→配置账号门槛与有效期→保存。房间服务依据房主等级生成资格结果。
2. **管理者发起**：符合资格房间的房主或管理员→底部房间工具→YouTube一起看→粘贴单视频链接→预览→确认开始。
3. **成员加入**：全房活动卡显示邀请→成员主动点击加入→必要时点击播放解锁本机播放器→跟随当前共享时间，继续语聊。不强制有声自动播放。
4. **共同观看**：房主/管理员均可全房暂停、继续或释放进度条后提交跳转；个人音量/静音/麦克风/放大/收起各自独立。
5. **管理者换片**：菜单或工具→更换视频→预览→确认。预览期间旧片保留，失败不影响旧片；成功原子切换、进度归零。已收起成员不被强制打开；静音和麦克风选择保留。
6. **管理者结束**：房主或管理员点结束→二次确认→全房结束视频，仍在语聊房。普通成员收起只停本机媒体，不结束会话。
7. **晚加入/返回**：读当前资格和会话快照，主动加入后跟随当前位置；暂停会话保持暂停；已结束不重开旧播放器。

只提交链接，不上传视频文件，不采集房主屏幕转播。每个人分别加载官方播放器，Hoki同步内容ID与共享状态。本期仍推荐仅语聊房单点播，不做搜索、播放队列、成员点播、直播/Shorts或后台听歌。

## 6. 资格/角色变化与管理者离线

| 变化 | 推荐处理 |
|---|---|
| 白名单停用/过期、总开关关闭、等级降到有效门槛以下 | 保存/事件确认后，重新判断所有受影响房间；不再具备资格则结束本场，停止媒体并隐藏管理入口，普通语聊继续。后台操作前提示影响 |
| 提高默认门槛 | 仅影响继承默认的账号；自定义与不限等级账号保持原规则；每个房间重算 |
| 降低门槛/财富升级/重新启用 | 达标后显示入口，但不自动发起、不自动恢复已结束的旧片 |
| 管理员被降权/移除 | 立即撤销该人的共享操作，关闭选片/结束弹窗、废弃旧预览；已加入观看可保留为普通成员。不因其个人降权撤销整房资格 |
| 管理员新增 | 有资格房间中入口即时可见；不自动加入或播放 |
| 管理员个人等级变化 | 不影响本房操作资格；判定使用房主等级 |
| 房主离房/断线，仍有其他房主/管理员在房在线 | 其他管理者继续操作，不再沿用“房主一离开全房结束” |
| 最后一名在线管理者离房/断线 | 共享暂停；推荐服务端确认后宽限30秒，任一有效管理者返回后保持暂停、主动继续；超时结束。主动离房先说明影响并确认 |
| 房主身份转移 | 推荐先结束当前会话，再按新房主资格显示入口；新房主/管理员主动重新发起 |
| 切游戏模式、解散房间或运营终止 | 按房间既有确认/通知结束会话，不把视频带进游戏层 |

即时收回、30秒和身份转移策略属于评审建议；正式发布前确认。服务端计算在线管理者集合，不能只看房主在线或只看当前发起人；管理员退出不会撤销他已发起的会话，只要还有其他管理者在线。

## 7. 并发、服务与数据

房间资格、房间角色、YouTube会话分三层，不把某个管理员个人白名单写入会话控制权。每次预览、发起、播放/暂停、seek、换片、结束均由服务端验证：账号在房、当前角色、房间资格、房型/地区/版本、会话与配置版本。仅隐藏按钮不构成权限校验。

原会话字段继续含room_id、session_id、media_version、video_id、duration、shared_state、position_anchor_ms、anchor_server_time_ms、revision。补充owner_uid、effective_policy_version、initiator_uid、last_command_actor_uid/role、end_reason、controllers_online_count。每条控制指令携带command_id、expected_revision、expected_media_version、expected_policy_version；服务端串行接受，返回新快照。

房主与多个管理员可同时操作，避免各端以本地状态各自获胜：后到的过期命令拒绝并刷新。共享跳转释放后提交一次；程序同步的播放器回调不再次发指令。预览绑定输入、角色、配置与会话版本；在其他管理者换片/结束后，旧预览不能覆盖新会话。原型用单页双角色模拟版本防护，真实多管理员并发待服务端验收。

播放目标 = min(duration, anchor + now_server − anchor_server_time)；暂停固定anchor。广告、缓冲、区域限制和自动播放被拦截独立处理，不跳广告、不让一位成员拖停全房、不承诺逐帧同步。个人恢复后取最新快照再纠偏。

推荐资格变更推送到受影响房间，按配置版本去重；推送丢失时，后续指令/进房/重连必须重新读取服务端结果。有效期按服务端定时及请求校验双重保障，不能依赖客户端本地时钟。白名单与门槛变更不新增钱包、工资、返奖或结算行为。

## 8. 沿用的观看交互与边界

- 保留紫色语聊房背景、麦位和底部工具，观看卡在麦位下方、公屏上方；公屏用紧凑紫色分类条，无游戏缩放按钮、居中箭头或绿色大遮罩。
- 官方播放器viewport至少200×200，保留官方控件/来源/广告；房间礼物横幅和动画不得盖在播放器上。原型画面、标题、时长和同步是假数据，不能当成官方最终UI。
- 普通成员邀请卡不依赖当前公屏Tab。公屏可点切Tab，真实手势仍遵循公屏切换v3.0；视频区手势归播放器，不触发房间横滑。
- 收起、播放器完全不可见、整屏公屏、后台/锁屏、切房时停止本机视频和声音，回来主动加入；共享会话按房间管理者状态继续或暂停。管理员后台配置评审面板是模拟另一个系统，不把切评审页面当作真实App生命周期。
- 视频音量与语聊/麦克风独立，不自动开麦；50%初始视频音量为推荐待评审。保留耳机建议；Android/iOS蓝牙、来电、音频焦点、外放回声需真机。
- 有BGM时推荐开始前提示，成功发起后暂停房间BGM；失败不暂停，结束后不擅自恢复。原型未接真实BGM。
- 支持普通youtube.com/watch与youtu.be短链接，严格白名单域名和合法video_id；首期不支持Shorts/直播/列表。实际类型、私密/删除/嵌入限制、年龄/地区等由官方服务验证，合法格式不保证播放。
- 官方播放器不用于隐藏后台听歌、抽音轨、下载转播、广告过滤、付费观看或观看激励。不收集YouTube账号密码、不绕过地区/年龄限制；正式接现有隐私告知、YouTube条款和Google隐私链接。
- 举报沿用现有房间体系，以会话与video_id关联，举报本身不自动结束；运营终止有审计。继承v1.0已经核对的YouTube官方要求。

## 9. 异常、埋点与发布

账号查无结果/重复白名单/门槛缺失/过期时间非法：弹窗内提示，保持输入；保存失败不改配置、不收回权限；版本冲突刷新后重新确认。准入未知/配置读取失败时不授权新的管理操作，不拿本地缓存永久授权，普通语聊继续。

播放器失败仅影响本机，发起/换片未确认成功不广播；提交失败取会话快照确认最终状态，避免超时重发创建两场。管理员降权后迟到回调失效，角色恢复不自动重发旧命令。

原有发起/加入/首帧/共享控制/本机控制/错误/结束埋点补actor_role、owner_uid、eligibility_reason、policy_version与end_reason。后台新增allowlist_create/update/enable/disable、policy_update、eligibility_changed；记录变更结果与影响对象。不向分析埋点上传原始带追踪参数的链接。

内部测试→地区/版本小范围→扩大，观察发起/加入成功、权限拒绝、过期命令、配置生效延时、误收回和音频投诉。正式开关初始值由运营确认，原型开启不代表上线默认。回滚到上一配置版本也必须重算资格，不恢复已结束旧视频。紧急停用按本轮建议结束会话；若要“只停新发起、存量续播”，应另设独立发布策略，不复用本准入开关产生两种含义。

## 10. 验收与待评审

1. 非白名单房主即使高财富也不授权；管理员自己的白名单不能替房主开通。
2. 白名单+默认门槛、自定义门槛、不限等级，及默认门槛关闭的组合均按公式判断；边界等级等于门槛时达标。
3. 添加/编辑/启停/期限/过滤/错误/保存失败有可复现状态，服务端审计与配置版本一致；过期记录重新启用仍不可用。
4. 同一有资格房间中，房主与管理员都能发起、换片、播放/seek和结束；普通成员只有本机观看控制。
5. 管理员降权立即撤权，不丢其普通观看；房间资格被收回时全员停媒体；恢复资格不自动恢复旧会话。
6. 房主不在、管理员在可继续；最后管理者离线暂停，返回保持暂停，超时结束；多管理员并发与旧预览/命令验证。
7. 手机后台表格内部滚动、弹窗不超宽；阿语客户端角色文案和RTL，原生YouTube/音频/跨设备同步专项验证。

待评审：准入采用本轮推荐AND模式与三种账号门槛是否采纳；正式财富等级字典及默认等级；白名单覆盖的区服/房间范围与有效期；资格收回时的即时结束策略；无人管理30秒宽限；实际运营发布权限/影响统计与音频/YouTube适配。

综合HTML已提供可操作默认方案供评审，不以这些待评审项阻断样式交付。真实后台持久化、服务端权限/推送、财富等级事件、跨设备同步、运营时区、母语审校和原生真机仍需接入。QA另见v2.0记录。
