# Hoki｜CP 2.0 升级｜PRD｜v6.0｜解除停用与复建恢复评审版

文档日期：2026-10-28（Asia/Shanghai）  
产品版本：CP 2.0；文档版本：v6.0  
适用对象：产品、设计、客户端、服务端、测试、运营、数据、财务、客服  
范围依据：用户本次首期拆分稿；从完整升级方案中提取首期以外的 CP 增量。已确认规则直接写为结论，真实数值冲突集中在第13节。

本次增量：CP1.0复用同一用户对的亲密值，解除后若只保留已发奖励包，会出现旧CP装扮继续可用或复建重复发奖的问题。本版按2026-10-28用户确认调整：同一段CP内降级不回收已解锁装扮、不加有效期；解除后停止该段CP奖励的使用资格；同对象复建复用双方当前亲密值计算CP等级，自动恢复对应等级权益，已有同款物料不重复叠发。新关系不自动继承旧段历史最高解锁资格，改建亲友/换对象不混用CP授权，永久证书保留。此前“复建成长初始化”不再解释为底层亲密值清零。

业务规则已按本轮确认写为结论；奖励包是否支持服务端使用限制、来源绑定、复用及旧端适配仍为研发核验项，不把产品确认写成技术已实现。CP房专属位具体占位细则仍是原提案，见13.6。另同步2026-10-27已确认的“幸运礼物不增加亲密值”，不擅自决定历史追溯或切换时点。

## 核心逻辑

- **首期先完成亲密关系底座**：兄弟、闺蜜、挚友及等级、申请/消息、席位、4日＋4周任务、基础 BOND/CP 礼物、好友列表和房间入口、私聊语音及 Profile 调整，均按首期交付。本版不重复立项。
- **CP 2.0 承接 CP 成长与权益升级**：CP Lv1–Lv100、每20级一个 G 档，统一为心动、默契、相伴、挚爱、永恒；引入五档物料、解锁记录与当前等级资格的区分，按本段CP解锁记录保留装扮，解除后停用、复建按当前等级恢复。
- **成长数据连续**：同一用户对的亲密值在解除后保留，重新结成任一关系仍复用；等级按当前关系类型的生效曲线计算。普通/活动礼物沿用原比例；幸运礼物不增加亲密值，历史记录及切换边界见2.2，不因复建注入额外成长。
- **CP 主页轻展示，CP Level 集中看权益**：主页保留等级、成长记录、纪念及管理；顶部双人展示区和等级卡均可进入同一个 CP Level 页面。完整档位奖励不常驻主页。
- **提升等级先展示礼物**：入口统一为“提升等级”，内部依次为“关系礼物 / CP 戒指 / 成长任务”，默认关系礼物；沿用自动到账，不增加领取动作或任务一级页签。
- **新增两款高阶 CP 礼物**：Lv10、Lv20 分别解锁，首期已开放的 BOND 和基础 CP 礼物不追加等级门槛。
- **新增CP关系展示开关**：个人主页设置页默认打开，控制个人主页、房间mini资料卡及「我的」主态的本人&CP双头像；双方各自控制本人页面，关闭恢复原样，详见第5.4节。
- **新增房间 CP 双人连线飘爱心**：所有房内用户均可观看有效 CP 双方之间的飘心，包含无CP的观众；双方须同房双上麦且麦位相邻，G1–G5各有对应表现；左右、正上下、四个斜角紧邻均可触发，详见第7.4节。全档均可展示，档位只决定样式。
- **装扮生命周期（已确认）**：同段CP内已解锁的头像框、背景、信息卡装扮及座驾等不因普通降级回收、不设有效期；解除后停用本段授权，物料和发奖记录可留存。复建按当前亲密值对应等级恢复使用权，不重复叠发整包；等级身份、房间效果与商品资格仍取当前有效等级。已获证书永久保留，见3–4及9。
- **解除后关闭旧关系入口**：旧关系日期、礼物、纪念、任务和流水不向用户开放，仅服务端按既有期限留存；已获永久证书继续展示。底层用户对亲密值不清零，新关系的日期/任务/纪念等按新实例统计，资产持有记录不等于使用资格。

## 2. CP 等级与存量成长数据

### 2.1 等级规则

| 档位编码 | 最终名称 | 等级范围 | 本档定位 |
|---|---|---|---|
| G1 | 心动 | Lv1–Lv20 | 基础身份与关系表达 |
| G2 | 默契 | Lv21–Lv40 | 关系视觉升级、房间个人信息卡装扮 |
| G3 | 相伴 | Lv41–Lv60 | 累计增加 CP 主页动态背景 |
| G4 | 挚爱 | Lv61–Lv80 | 累计增加 CP 专属座驾 |
| G5 | 永恒 | Lv81–Lv100 | 累计增加一次性永久荣誉认证证书 |

- 服务端从唯一生效的 `level_rule_version` 读取100级累计门槛：`calculated_level = max{L | threshold[L] <= effective_intimacy}`。有效存量 CP 低于最低等级门槛时按 Lv1 展示，不因此解除。
- `calculated_level` 是实时计算值；`relationship_level` 是按保护规则生效的展示等级；`rights_level` 是保护生效后的当前业务资格等级，用于商品资格和当前等级表现。保护期内后两者可高于实时计算值；装扮使用另读本关系的已解锁记录，不再以当前等级反向剔除已解锁装扮。
- 正常进度读取本级、下一级门槛和差值；Lv100 显示已满级及溢出值，亲密值仍可继续累计。保护期间展示恢复目标、差值和截止时间，不拼接负数进度。
- 单笔跨多级一次计算最终结果，补齐最终可用资格，前端合并一次升级反馈；每5级的轻量反馈复用本档素材，不新增一套奖励。`highest_level_achieved`记录当前关系已有效确认的最高等级，用于档位解锁及幂等核对；支付与等级效果不以最高值代替当前`rights_level`。异常撤销需单独审计，不能仅用未经核验的原始峰值确认已解锁。
- **用户对亲密值与关系实例分开**：双方UID确定用户对；同对象解除、复建或改建关系类型仍使用双方当前有效亲密值，等级读取该关系类型的生效曲线。新relationship_id不代表亲密值清零，不新建重复CP EXP账本；A/B与A/C的亲密值分别计算。
- 结成资格判断与等级映射是不同业务用途，字段可分开返回，但本版不再假定它们来自两个独立余额。首期CP门槛/戒指结算仍依赖首期核对，不用“Lv1起点”反向改写资格或向余额注入起始值。
- 新CP建立成功时，服务端主动按双方当前亲密值初始化本段等级与可用权益，不等待后续升级事件。旧段highest_level_achieved、装扮授权和保护截止不直接复制到新段；新段从本次合法初始化等级记录最高达成，之后按本段升级继续追加。恢复细则见9.3，账户字段与唯一曲线映射见13.2。

- 幸运礼物“不增加亲密值”的生效切换时间及历史追溯未由本轮裁决。本版不自动回算、扣减或补偿历史余额；历史流水保留原规则版本与入账结果，迁移不得擅自重估。普通/活动比例同样不在本轮重算。

- 复用现有衰减服务及免衰条件，不新增 CP 2.0 定时扣减，不把打开主页、任务奖励或纯时长自动当作免衰行为；衰减不产生“CP 冻结”关系状态。

### 2.3 存量迁移

1. 上线前保存用户对标识/成长账户、relationship_id、有效亲密值及余额版本、当前等级/档位、本段历史最高等级、已发资产来源/使用授权、永久奖励及旧规则版本快照。
2. 在账户单位/映射核对后，按唯一曲线重算 CP 等级和档位；**不清零、不补算历史成长、不另建一套 CP EXP 账本**。
3. 迁移不伪造关系建立、送礼、任务或成长流水，不刷升级通知，不重复发放奖励；当前业务资格按迁移结果映射，当前有效CP段内已合法解锁装扮按可核实记录保留，已解除来源不得因迁移重新激活；证书按已获记录保留。旧系统无资产来源/解锁记录时按13.2确定映射，不伪造高档授权或重复整包发奖。
4. 新曲线导致的迁移降档与日常衰减分开标记，不伪装成某日衰减；迁移保护/生效批次按第13节唯一发布方案落实，不能客户端自行套一轮7天。
5. 有效关系不因低于新门槛而解除。关系起始时间、任务原周期、礼物原订单与已购席位不变。

**注意：**旧表与旧 PRD 的等级曲线确有冲突，本版不复制一张未经统一的100行表作为正式配置。迁移是否构成 G5 证书首次达成也不能由客户端自行推断，见第13节。

- 今日4条、本周4条上下连续展示，不再嵌套日/周 Tab；每组显示完成数与到账额度，每项显示明确条件、进度、奖励和动作。达标自动到账，无领取按钮。

## 8. CP 纪念、关系信息与解除前回顾

- 协议同意、强制解除、超时和重复点击竞争时以服务端事务最终态为准；关系已被解除返回既有结果，不能再次扣款或重新占位。

### 9.2 解除成功：关闭旧入口与停用授权

- 仅在正式解除成功时停用；协议解除待对方同意、取消、支付失败或明确未解除时，不提前撤销当前有效CP权益。超时查询原请求最终态，不能只看本地弹窗。
- 立即清理个人主页、房间mini资料卡及「我的」主态旧CP双头像并恢复普通样式，保留账号级展示偏好；关闭旧CP主页、CP Level、成长记录、纪念/回顾入口，清理缓存。用户侧不返回已解除实例的礼物、纪念、任务、流水等详情，旧深链回当前入口。
- 服务端使来源于本段CP的装扮授权失效，停止已装备/房间/进场效果，恢复默认；后续背包装备、应用、展示与旧接口均不得绕过。发奖/资产持有记录可保留，不要求删除整包，不以仅隐藏或卸下当前装备替代使用拦截。
- 只有本段CP来源授权失效；其他活动/购买等独立合法来源的同款资产保留其权限。原房间Admin等管理权限按自身规则，不因CP解除增减。
- 已获永久证书继续在个人荣誉展示，不提供旧关系跳转。旧订单、任务、纪念、流水及授予/失效审计仅服务端按既有期限留存供授权客服查询。保留物料记录不代表继续开放旧CP权益或旧关系详情。
- **同一用户对亲密值保留**，解除不清零、不注入起始值。旧事件和退款仍关联来源订单/关系审计；如实际影响共享亲密值，可影响后来有效关系等级，按2.2刷新，不能误写成新关系新增旧订单。
