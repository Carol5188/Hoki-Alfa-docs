## 2. 成长、衰减与等级计算

- [ ] Lv1–Lv100，G1–G5 每档 20 级：G1=1–20、G2=21–40、G3=41–60、G4=61–80、G5=81–100；计算使用正式累计门槛，不能采用原型演示进度。
- [ ] Lv100 后亲密值继续累计并保留溢出；历史最高等级只增不减，首次奖励与再次达成分开处理。
- [ ] 基础行为值和任务奖励分来源入账：私信双向回合 +1、上限 20/日；共同游戏 +10、上限 30/日。普通/活动礼物按实付金币/100，幸运礼物按 floor(实付金币/1,000)，普通礼物取整须核验现网规则。
- [ ] BOND/CP 礼物按固定成长值入账，不再叠加一遍普通礼物公式；幸运返奖、中奖倍数、免费或背包来源不放大正向成长。
- [ ] 衰减沿用现网服务，不增加第二套定时器。PRD 默认每天 22:00（UTC+3），当日同时无有效送礼、有效私聊回合和共同游戏时扣 50，最低 0；上线前核对现网时区与口径。
- [ ] **同房、同麦时长及任务奖励本身不免衰减**。即使完成陪伴任务，也不能直接据此判定当天免衰；有效送礼、私聊双向回合或共同游戏才满足现有免衰条件。
- [ ] 每段关系每日只产生一笔衰减流水；增长、衰减、退款和撤销并发时按服务端事件时间及账户版本处理，不重复扣减。
- [ ] 无互动 7 天为召回提示、14 天为“待关心”展示，关系仍有效；不恢复已删除的 CP 冻结状态或冻结送礼分支。

## 3. 权益掉档与恢复——本轮重点

- [ ] 正常衰退触发保护后，**7 天内保留原档全部持续型权益**，包括背景、座驾、信息卡、勋章、铭牌、主页框和麦位视觉。
- [ ] 保护页显示服务端截止时间、恢复所需差值；保护期内恢复原门槛，取消降档且不重复发奖。
- [ ] 保护到期仍未恢复时，服务端下调 `rights_level` 并记录待刷新状态，关系本身保持有效，不能把掉档等同于解除关系。
- [ ] 当前 App 会话不强制热切背景、座驾或信息卡；**下次冷启动或重新登录**读取最新权益状态并卸下超档资源。普通后台切回前台仍属当前会话；进程终止后的再次启动属于冷启动。
- [ ] 单 Lv、跨 G 档、连续下降的判定沿用 PRD 5.4 与现有保护服务，不新增触发或重置规则；保护截止时间取服务端值，客户端不因再次下降自行重新计时。
- [ ] 回退优先使用当前档位同类型最高可用资源；没有同类型资源时使用系统默认。例：G4 掉至 G3，座驾不再可用，但仍可使用 G3 背景与信息卡。
- [ ] 到期待刷新期间，礼物资格等新操作仍按服务端最新 `rights_level` 复核，不能用当前会话尚未卸下的资源或旧等级缓存绕过支付校验。
- [ ] 重新升级自动恢复对应持续型权益使用资格及资源，不要求重复购买或领取，不重复发资产、证书或公共升级通知。
- [ ] **G5 荣誉认证证书是首次获得后永久保留的奖励**：掉档不隐藏，解除后仍在个人荣誉查看；保存原关系、双方、首次获得时间与编号，重复达成不生成第二张。证书无旧关系跳转，不返回旧礼物/纪念/流水。
- [ ] 新旧客户端使用同一服务端 `rights_level`、保护截止时间和状态版本；旧端不支持新素材时使用默认资源，不维护第二套权益等级。
- [ ] 关系解除后持续型权益和关系展示立即失效，信息卡立即回退默认；不能套用“等下次进入App”。永久证书个人荣誉展示，其他历史数据仅服务端留存，不向用户展示。
- [ ] 退款、拒付、作弊撤销不自动获得正常衰退保护；必须绑定原事件并有审计与复核结果。

- [ ] CP Gifts 至少区分 CP 礼物、BOND、普通、幸运；普通/幸运展示汇总基础件数。幸运中奖倍数、返奖和播放动画次数不增加件数。
- [ ] 失败、退款、拒付、撤销不计最终件数；普通礼物汇总包含普通与活动成功基础件数，不新增活动礼物卡，Gifts 总数不重复累计。原订单商品类型继续保留用于退款与审计。
- [ ] 原型示例 Rings=5、Gifts=31、总计=36，普通=18、幸运=6 仅用于核对展示算术；真实端按当前关系聚合数据展示，加载失败不能显示为“0 资产”。

## 10. 四类关系解除

- [ ] CP、兄弟、闺蜜、挚友页底部都有解除入口，共用回忆页和确认组件，称谓、主题、伙伴、资产及费用随当前关系切换。
- [ ] 协议解除和强制解除均有**中央二次确认**；取消保持原关系与回忆页，确认才提交。不能与礼物商品直接发送逻辑混用。
- [ ] 协议解除须对方 1 天内同意；明确拒绝或超时未响应均结束申请，关系保持有效，不自动解除。无冷却期，可立即重发；存在待处理申请时防重复创建。
- [ ] 强制解除默认价 CP **99,999 金币**、亲友 **59,999 金币**；读服务端配置，价格变化须重新确认，配置缺失不能以本地默认价扣款。
- [ ] 余额不足、关系已解除/类型变化、重复点击和超时均不重复扣款，不提前清空关系或资产；重复请求可查询最终态。
- [ ] 免费即时安全解除、屏蔽、举报始终独立可达，不被付费或等待对方同意阻断。
- [ ] 解除后旧主页/关系卡/戒指/礼物/纪念/流水及其他旧关系信息不展示，用户历史入口不新增；旧深链、缓存、页面栈及用户查询接口也关闭，证书个人荣誉查询独立可用。
- [ ] 数据仅服务端按现有期限留存，供授权客服/审计查询；客户端清旧缓存，权限校验不能只靠隐藏入口。
- [ ] 新关系生成新ID、开始时间并按建立规则初始化；同对象复建也不继承旧成长、任务、礼物、纪念或流水。旧关系迟到退款/回调绑定原ID，不串入新关系；已有证书不计新关系统计。

## 11. 客户端、接口与上线验收

- [ ] 房间复用入/离房、上/下麦、心跳、文字/表情和已有发言事件，服务端去重并计算双方有效时长交集；旧端缺新事件先用等价可信服务端事件，证据不足不猜计时、不放宽任务条件。
- [ ] actual_coin_cost来自实际钱包扣款与收礼子单，多人礼物不重复计整批金额；退款/拒付/撤销绑定原子单回退成长、任务进度及不再满足条件的任务奖励，不影响其他关系或仍达标任务。
- [ ] 每套动态资源附静态图，复用现有播放器。首轮压测采用单动画≤2 MB、≤24 fps，信息卡同时只播一个；离屏/后台暂停，低端机/资源失败静态或默认降级，最终性能预算以目标机型实测落实。
- [ ] 按平台/build核验关系、权益、任务和钱包能力，服务端维护版本能力映射；业务正确的旧端允许静态/默认展示，新端低端机性能不足也用静态降级。
- [ ] 旧送礼端业务不安全时，在订单创建/扣款前拦截并提示升级；旧接口、缓存和深链不能绕过，无订单、无扣款，不默默转普通礼物或旧支付流程。
- [ ] 新送礼端→旧收礼端可由服务端正确验证/结算时允许收礼并兼容展示，不因动画不支持要求双方强更；已成功订单以服务端最终态处理，不因升级/播放失败重复扣款或退款。
- [ ] 双版本建立/协议解除分别核验操作者最低版本；升级提示不清关系、不改申请时限。任务必要事件无法取得时提示升级受影响流程，不伪发奖。
- [ ] 优先限制受影响CP功能；服务端不能正确拦截且旧接口无法隔离时才对受影响平台/build强更。返回/升级失败保留房间、合法关系与数据，安全解除/屏蔽/举报独立可达。
- [ ] 服务端字段缺失补接口，低端硬件不足用静态降级，不能用强更替代；核验新→旧/旧→新/旧→旧及低端新端、断网、超时、部分退款和状态变化。
- [ ] 至少走通 10 个礼物场景：CP Lv5/Lv15/Lv25、仅亲友无 CP、无正式关系、对象下麦、对象离房、CP 离房、身份穷举、支付前关系变化。
- [ ] 至少走通 5 类权益状态：保护保留、到期待刷新、冷启动/重新登录应用回退、重新升级恢复、永久证书；另覆盖解除后的立即失效。
- [ ] 补齐加载、空数据、错误、余额不足、重复提交、超时重试、多端并发与素材失败；加载失败不能伪装成无关系或无资产。
- [ ] 中文/英文/阿语的长昵称、数字、价格、时间、按钮及 RTL 正确；通知遵循双方更严格隐私范围，生日明文及风控因子不进入埋点。
- [ ] 服务端保留关系、任务、权益状态版本、订单子单、退款/补偿和解除审计；曝光、点击、结果、失败、回退及恢复有可查埋点。
- [ ] 灰度前核验现网口径并做至少 7 天只读影子计算、近 30/90 天流水回放；资源、礼物、路由和解除有独立开关，回滚不删除合法余额、订单、纪念或证书记录。
- [ ] 当前版本已完成双入口的真实浏览器增量验证，以及静态脚本、资源、规则结构和表格公式检查；完整支付、任务及解除流程仍须进行上线回归。
- [ ] 对外分享须重新打包完整素材或发布 v2.55 在线版；历史 v2.48 包和过期链接不能用于本轮评审。
- [ ] v2.55 本轮增量已验证顶部鼠标/键盘与等级卡两入口、当前档位、奖励中央预览、返回位置及 About CP 独立交互；该验证不替代完整支付、任务和解除流程的上线回归。

- [ ] **永久证书实施**：持续型权益不可用与证书“永久已获得”分开表达；个人荣誉入口独立，不带出旧关系信息。分享正式称谓/权限继续按已有待确认范围收口。
