# CP 数据看板：指标口径与接入需求

版本：v1.1；评审日期：2026-10-08（Asia/Shanghai）。  
页面：同目录 `CP｜数据看板｜HTML原型｜v1.1｜可评审版.html`。  
规则参考：PRD v5.14、个人主页原型 v2.55、成长表 v3.9。  
展示品牌：Hoki，左上角字母标识为 H；历史模板中的品牌名不继承。  
样式参考：CP 管理后台 v1.0 的黑色侧栏、白色卡片、绿色强调色、筛选与明细表。

本版交付六个可切换的看板，用于评审指标、交互与数据归属。HTML 全部使用生成的示例数据，不调用生产接口；示例 UID、关系 ID、金额、比例、等级快照和戒指参数均不作为真实经营结果或正式配置。

## 1. 范围与当前裁决

| 事项 | 本版处理 |
|---|---|
| 统计对象 | CP 关系；亲友数据不并入 CP 规模、成长或消费 |
| 礼物范围 | 当前 CP 双方互赠并归属该关系的子单；同时区分普通、活动、幸运、BOND、CP 专属礼物、求婚/升级戒指 |
| BOND 混合批次 | 只统计 CP 子单；同批亲友子单保持独立，不把批次整单重复累计到 CP |
| 时间与筛选 | 最近 7/30/90 个完整业务日或自定义；大区、期末 G 档、关系 ID/任一 UID；查询条件跨看板保留 |
| 统计时区 | 原型采用 UTC+3 业务日；正式统计时区由数据团队确认。任务周期沿用关系建立分区，不据分析时区重新切周期 |
| 无分母 | 显示 `—`，不显示 0% 或 100%；无样本仍能调整筛选 |
| 数据操作 | 查询、详情、导出只读；不能修改关系、亲密值、金币、任务或权益 |
| 共享方式 | 单文件 HTML，CSS/图表/示例数据均内嵌，离线打开不丢素材 |

## 3. 统一粒度与筛选

| 对象 | 主键与统计边界 |
|---|---|
| 关系 | `relationship_id`，双方为一段关系；复建生成新 ID，不把前后两段合并 |
| 用户 | UID 去重；同一 CP 的双方可能是两名付费用户，用户数不能等同关系数 |
| 发送动作 | `batch_id`；一个 BOND 批次可含多段关系 |
| 金币与件数 | `suborder_id`，按子单归属 CP；部分退款按剩余金额和基础件数冲减 |
| 亲密值 | `ledger_id` 去重，`source_type` 互斥分类；原始正向与撤销流水同时保留 |
| 任务 | `relationship_id + cycle_id + task_code`；双方共享，不按客户端回调重复计算 |
| 权益 | `relationship_id + snapshot_date + rights_state_version`；永久奖励另按 reward code 去重 |
| 漏斗 | 申请/引导实例 ID，按同一队列顺序统计；不混用曝光 PV、用户 UV 与关系对数 |

日期开始与结束都包含。正式接口采用 `[start_at, end_at_exclusive)`，由时区转换生成时间戳，不能用裸日期直接筛 UTC 时间。

大区按关系建立时发起方业务归属分区统计，不能在同一周期跟随用户旅行/语言切换。原型提供四个大区用于交互评审，不代表正式大区枚举。

G 档筛选采用**结束日计算等级快照对应的关系集合**，集合内所有区间事件都纳入。需要“事件发生时 G 档”时另建 event-stage 维度，不复用该筛选；期末档位集合变化不能算新建、解除或成长。

关系 ID / UID 为精确匹配；查询 UID 返回其对应 CP 段，正式服务支持历史多段且遵从查询权限。礼物分类只影响礼物页的趋势、卡片、子单与导出，分类汇总保持全部分类并明确标注。

## 4. 关系规模与留存

| 指标 key | 展示 | 定义 / 分母 |
|---|---|---|
| `cp_active_at_end` | 期末有效 CP | 结束日仍有效的去重关系数；保护期不影响有效性；terminated 排除 |
| `cp_created_count` | 区间新建 CP | 创建成功时间在区间内的 relationship_id 数；接受申请失败不计 |
| `cp_terminated_count` | 区间解除 CP | 服务端最终解除成功时间在区间内；申请、拒绝、超时、取消不算解除 |
| `cp_behavior_active_count` | 区间活跃 CP | 区间内有效私信、游戏、成功送礼或任务达成的去重关系数；包括期中解除前活跃的关系 |
| `cp_paying_relation_ratio` | 付费 CP 占比 | 期末有效且区间有净送达金币礼物的 CP / 期末有效 CP，分子限同一存量集合 |
| `cp_d7_retention` | D7 行为留存 | 区间新建队列中，精确第 7 个业务日仍有效并有有效互动/成长的关系 / 已成熟关系 |
| `cp_d30_retention` | D30 行为留存 | 同上，观察第 30 日；未满 30 日不加入流失或分母 |
| `cp_apply_step_conversion` | 建立漏斗 | 区间首曝申请实例→开始申请→提交→接受建立；逐步转化分母为上一步同队列实例数 |

解除按协议、强制、安全三类分解。CP 强制解除默认 99,999 金币独立入账，不并入礼物消费；安全解除免费独立可达。

申请漏斗按首曝/创建队列回溯，截至结束日的处理结果。未决申请不计 accepted，需输出 pending/未成熟数量；D7/D30 与漏斗都不能将观察窗不足当失败。

按期末等级或单个已建立关系筛选后，未建立申请无法归属等级/关系，漏斗仅代表可归因申请，不代表全量建立转化。原型在漏斗下提示此限制。

## 5. 亲密值：来源、余额与成长

| 来源 | 正向值 / 规则 | 看板注意事项 |
|---|---|---|
| 私信互动 | 有效双向回合 +1，20/日上限 | 成功回合事件，不能按消息总数替代 |
| 共同游戏 | 有效游戏 +10，30/日上限 | 取结算成功，游戏回调去重 |
| 普通/活动礼物 | 本次实付金币÷100，沿用现网取整 | 两种分类分别保留，背包/免费/运营/全额券不作为本次消费成长 |
| 幸运礼物 | `floor(actual_coin_cost / 1,000)` | 按普通增长比例的 **10% 计入**；不是减去10%；中奖/返奖/倍数不计成长 |
| BOND | +350/件/关系子单 | 子单发放成功；不能再叠加普通礼物公式 |
| CP 专属礼物 | Lv1/Lv10/Lv20 分别 +600/+1,750/+6,000 | 读取配置与订单时版本；价格不直接反推成长 |
| 求婚/升级戒指 | 现网商品配置记账值 | 单独来源；不完成日/周送礼任务；示例戒指参数非正式配置 |
| 每日任务 | +10/条，40/关系/日 | 与行为成长分开，双方共享一笔奖励 |
| 每周任务 | +20/条，80/关系/周 | 不额外发宝箱、总完成奖或领取奖 |
| 创建注入 | 建立成功时 +1,000，幂等一次 | 单列，不计自然成长、活跃、礼物成长或任务成长 |

**余额桥接：**期末有效亲密值 = 同关系集合期初余额 + 区间正向成长 + 创建注入 + 其他合法正向调整 − 衰减 − 礼物退款/撤销 − 任务奖励撤销 − 其他合法负向调整。正式接入如存在运营补偿，必须新增独立调整来源，不能悄悄写入普通礼物。

历史存量余额使用原值，不清零、压缩或追溯施加幸运折损。原型用存量示例余额加流水生成期末值；展示来源占比时排除创建注入。来源关系数重叠，不跨行加总；流水数和变动金额可按互斥 source_type 加总。

P50/P90/P99 对期末有效关系的有效亲密值计算；原型使用排序后线性插值，正式引擎明确 `percentile_cont` 或等价算法、空值处理和样本量。样本很少时不可把P99解读为稳健的头部统计。

“非付费成长”包含私信、游戏、三条非付费日任务和三条非付费周任务；送礼任务奖励不并入非付费。同房/同麦没有额外基础值；任务达成不代表免衰。默认免费周上限仍为620，正式排查取服务端已入账值。

## 6. 礼物与金币

| 指标 key | 定义 |
|---|---|
| `cp_gift_net_quantity` | 成功送达基础件数 − 退款/撤销件数；不放大幸运倍数、返奖、动画次数 |
| `cp_gift_net_coin` | 已送达CP子单实付金币 − 已退款/撤销金额；排除失败与待发放，不作为财务收入 |
| `cp_gift_payer_uv` | 至少一个净送达CP子单且实付>0的发送方UID去重；跨分类付费用户重叠 |
| `cp_gift_repeat_payer_ratio` | 区间至少2个净送达子单的付费UID / 净付费UID；称为“区间重复送礼”，不冒充跨期复购留存 |
| `cp_gift_coin_per_payer` | 当前分类净金币 / 当前分类净付费UID |
| `cp_gift_coin_per_growth` | 当前分类净金币 / 当前分类净礼物成长；不含送礼引发的任务奖励；零成长显示— |
| `cp_gift_refund_coin` | 区间退款发生日的退款/撤销金币，另保留原订单日期供回溯 |
| `cp_gift_pending_coin` | 已扣未送达且未退款的CP子单金币；补偿积压另统计账龄 |
| `bond_batch_recipient_mean` | 涉及CP的去重BOND批次的收礼关系数均值；可含亲友人数，但不把亲友金币归属CP |

原型金币按同日全额退款演示，能核对：**已扣金币 = 净送达金币 + 已退款金币 + 已扣待发放金币**。正式系统有跨期退款、部分退款/发放、补偿、拒付时，用期初/期末钱包和待发放余额桥接；不能把跨期现金流强行套入该同日公式。

礼物分类与财务子单分类一一映射。活动礼物不并入普通礼物；Relationship Memory是否增加活动礼物卡不影响后台独立分类。戒指单列；强制解除不是礼物。幸运返奖/RTP/奖池/主播工资/公会结算为独立账务，本看板不称“利润”或“财务净收入”。

关系礼物配置参考：BOND 18,888金币/+350，CP三档29,999/+600、69,999/+1,750、199,999/+6,000。正式读取订单配置版本；调价不回写历史订单。

原型只生成金币实付订单；正式后台如需展示背包、免费、运营赠送件数，增加gift_source筛选和独立数量指标，不给其虚构实付金额或成长。

## 7. 自动成长任务

| 周期 | 固定任务 | 单项奖励 |
|---|---|---:|
| 日 | 亲密聊天、同房陪伴、同麦陪伴、送份礼物 | +10 |
| 周 | 三日相伴、常伴在麦、五日有互动、关系升温 | +20 |

`任务完成率 = 曾达成实例 / 可统计实例`；曾达成分解为净已到账、目标达成待到账、已撤销三类。`净自动到账率 = 净已到账实例 / 曾达成实例`，需同时展示撤销，避免把撤销误认为发送失败。

`净任务奖励 = 奖励正向流水 − 撤销流水`。以实例幂等键归因，不按双方UI的回调或页面完成人数发两次。没有领取率、待领取、手动领取页面。

周任务只纳入开始/结束完整落在当前区间的周期；每日按任务实例业务日期统计。新关系当前周期只计建立后行为，不补历史；解除中断周期需明确eligible/expired实例分母。原型未纳入解除中断的周周期，正式以任务服务返回的资格为准。

送礼必须本次消耗金币；背包礼物不计。同笔合格关系礼物可以完成日“送份礼物”和周“关系升温”，两项奖励分开；求婚/升级戒指不计两者。退款可以撤销两类任务，跨期仍关联原周期。

## 8. 等级、权益与页面入口

| 字段 / 状态 | 看板用途 |
|---|---|
| `calculated_level` / `relationship_stage` | 即时计算等级与G档；G1—G5每20级，服务端快照为事实源 |
| `relationship_level` | 客户端保护期展示等级；不得自动等同即时计算等级 |
| `rights_level` | 服务端允许使用的持续型权益等级 |
| `effective_rights_level` | 当前App会话已应用的权益等级；多个会话必须明确会话粒度，不能任选一条冒充整段关系 |
| `normal` | 正常资格与应用状态 |
| `grace` | 7天保护保留原档全部权益，显示截止时间 |
| `downgraded_pending_refresh` | 到期未恢复，服务端已降档；当前会话允许等待下次冷启动/登录应用 |
| `downgraded_applied` | 客户端已回退到当前最高可用资源或默认 |
| `restored` | 重新升级恢复资格，不重复发奖或公共升级通知 |
| `permanent_reward_codes[]` | G5荣誉证书首次获得后永久保留，掉档/解除均不删除 |

权益资格覆盖：G2+个人信息卡、G3+动态背景、G4+座驾按rights_level统计，跨行覆盖重叠不加总。永久证书拥有记录可包含已解除历史关系，不能用“当前G5人数”替代。

正式客户端应用状态需分别返回本人/伙伴会话，或定义“双方均已应用 / 至少一方待应用 / 无在线会话”。原型用一个代表性会话展示字段关系，正式不得沿用成未经定义的关系级指标。

CP Level两个入口记录 `cp_level_entry_source=hero / level_summary`：入口曝光/点击、成功打开、返回、权益预览。原型显示点击→成功打开与预览点击；正式补曝光UV、CTR、去重导航ID、失败稳定码及房间恢复结果。两个入口打开同一页，不能重复算两次页面成功曝光。

CP冻结状态已删除，看板不增加冻结人数、冻结成长或冻结送礼统计。

| `cp_application_event` | application_id、navigation_id、用户/双方UID、region、eligible、step、event_at、result、resolved_at | 申请服务/埋点；漏斗同队列、资格阈值1,000、待处理截止 |
| `cp_page_event` | event_id、navigation_id、relationship_id、uid、page、entry_source、action、event_at、result/error_code、room_resume_result | 埋点；CP Level双入口与房间恢复，不暴露风控因子 |
| `cp_termination_event` | request_id、relationship_id、method、requested_at、result、terminated_at、coin_cost、price_version | 关系/钱包；协议、强制、安全区分，金币独立 |

正式聚合建议：总览/日趋势/来源/礼物/任务/权益/留存分别提供查询接口，共用filter对象并返回`scope_summary、data_as_of、timezone、rule_versions、currency、grain、sample_size、is_partial`。详情接口按关系或子单查事实记录，不复算金额。

分页由服务端返回total与cursor；导出基于完整筛选异步生成，不只导出当前页。聚合读数与导出使用同一数据版本，延迟更新应显示data_as_of。多个接口部分失败时区块可重试，不能让旧指标与新明细混在同一对账式里。

## 10. 权限、异常与发布

运营/产品看聚合；客服看授权关系详情；数据/财务看许可范围内明细与导出。UID可脱敏，完整查询与导出使用独立权限；日志记录操作者、范围、数据版本、导出结果和时间，不记录公开敏感内容。看板不提供后台发奖、扣款或直接改亲密值功能。

空、加载、请求失败、重试、日期反向、未知ID、无成熟留存分母均有真实控件和状态。切换看板及请求重试保留筛选，加载失败不冒充0；导出按钮在空/加载/失败时禁用。CSV使用UTF-8 BOM、标准引用并防公式注入。

正式发布采用只读灰度：先对历史流水/余额、钱包/子单、任务奖励做影子核对；再开放聚合和授权明细，最后开放导出。回滚关闭入口/导出即可，不改业务数据。告警包括余额桥接差异、子单重复、任务重复入账、撤销遗漏、补偿积压和会话状态长期不收敛；阈值由数据与运营确定，不在原型虚构“安全阈值”。

本版后台文案为中文；英文/阿语后台是否需要另建i18n由后台使用人群确认，不宣称三语/RTL已验收。客户端业务文案仍以PRD已有稳定key为准。
