# Hoki｜公屏消息切换｜竞品对齐方案

v3.0｜可评审版｜2026-10-22（Asia/Shanghai）

## 1. 本次裁决

**按用户提供的竞品录屏重做公屏组件：缩放按钮、分类条、大小公屏的位置与遮罩表现均以竞品为准。**

用户已否定 v2.0 的“复用现平台居中上/下箭头、深绿色大面板”方案，原因是遮盖游戏、按钮不好按。该方案及旧标注图停止作为设计或开发依据。现平台截图只用于识别需要改造的结构，不作为新公屏视觉模板。

| 项目 | v2.0 旧方案 | 本轮裁决与来源 |
|---|---|---|
| 游戏房缩放入口 | 沿用公屏上沿居中上/下箭头 | 改为竞品公屏左上角的四角展开/收起按钮，紧挨分类条。用户本轮明确要求按竞品走 |
| 小公屏 | 原消息气泡上叠加大块三 Tab 行 | 透明公屏；紧凑分类条放在游戏操作区下方，按竞品样式做 |
| 大公屏 | 现平台深绿色大面积容器 | 竞品局部黑色半透明面板；仅面板所在区域变暗，上部游戏画面保持原亮度 |
| 分类条 | 全部/聊天/礼物常驻宽行 | 复刻竞品“当前项＋箭头”与展开后的横向三项形态 |
| 聊天房 | 曾建议新加“返回房间”导航条 | 沿用竞品房间/整屏的横向视图结构，不另加与录屏不同的常驻导航条或缩放按钮 |

此表已按用户最新指令完成裁决，不再把“是否继续复用旧遮罩和旧箭头”列为待确认。

| 游戏展开 | 第一段 03/04/49/52 秒 | 面板上沿上移，局部黑色半透明背景；四角图标改为向内收起，仍在公屏左上角 |

## 3. 游戏房改造

### 3.1 小公屏：默认保留游戏操作空间

1. 按竞品布局，将游戏主体、人数/费用/座位以及 Join/Start 等关键操作完整排在小公屏上沿之上。现平台下方留白和游戏模块间距一起调整，为公屏让出独立位置；不能把新公屏直接叠到现有 Join/Start 上。
2. 小公屏背景透明，保留房间背景；消息自身气泡按竞品半透明方式展示。不保留深绿色整块底板，不在小公屏状态增加整页遮罩。
3. 左上角放四角向外的展开图标，右侧紧接紧凑分类条。它们是一行小型控件，不占据游戏操作区中间位置。
4. 分类条收合时显示“当前分类＋箭头”，例如 `All ›`；点击箭头展示横向 All / Chat / Gift，可点击指定项。分类条的展示/收合与公屏大小是两个独立操作。
5. 底部输入、礼物和工具入口沿用本品业务，但布局与公屏的间隔按竞品处理；不挤压游戏按钮。

### 3.2 大公屏：复刻竞品的局部阅读面板

1. 点击左上角四角展开图标，公屏上沿上移到竞品对应比例；图标变为四角向内收起，分类条随公屏上沿移动。
2. 面板采用黑色半透明背景，遮罩限定在公屏展开区域；公屏上方的游戏画面、房间头部与麦位不加全屏变暗层。
3. 竞品展开态确实覆盖游戏下部的一部分。按该行为复刻：这是用户主动展开后的阅读面板，不能承诺“展开也完全不覆盖游戏”；小公屏必须完整露出关键游戏操作，收起后立即恢复。
4. 面板覆盖区域归公屏处理，点击不穿透到下方游戏按钮。露出区域继续归游戏自身处理；展开/收起不退出、不重开游戏。
5. 不保留顶部居中上/下箭头，不保留现平台深绿色展开层，不新增整条拖拽把手。右下的小箭头不拿来替代左上角四角缩放按钮。

### 3.3 点击与热区

- 展开、收起均点击同一类左上角四角图标；图标视觉、位置、与分类条的间距按竞品截图对齐。
- 原生可点击热区按客户端既有可用性规范扩展到公屏控件行内部，不能向游戏操作区延伸，也不能与分类箭头或 Tab 热区重叠。具体逻辑点数待客户端测量，不假称录屏已给出触控面积。
- 游戏画面、麦位、背景等非公屏区域不注册公屏视图横滑；公屏内横滑继续切换消息分类。游戏有无进行、本人是否参局都不改变此规则。

## 4. 聊天房：按竞品横向切屏

- 房间视图保留麦位与下方公屏，采用同款紧凑分类条；没有游戏房的四角展开/收起按钮。
- 在非公屏的可响应区域横滑，整体进入整屏公屏；进入后麦位从视图移出，公屏使用房间头部下方到输入工具栏上方的主要空间。
- 切换采用竞品房间内的横向过渡，不套用游戏房的黑色放大面板，不新增绿色遮罩、上/下箭头或常驻“返回房间”导航条。
- 反向切换仍由非公屏可响应区域处理，整屏中使用保留的房间头部空白区域；系统返回先关闭键盘/上层面板，再回房间视图。需无障碍时提供等价动作，不增加可见装饰控件。
- 方向按现有录屏转场和客户端 LTR/RTL 规范对齐；点击头像、工具、活动卡片、输入等仍优先交给原控件，不能被透明全屏手势层抢占。

## 5. 公屏内的 Tab 切换与状态

公屏共用 All / Chat / Gift（中文：全部/聊天/礼物）。本轮按竞品复刻分类条的折叠形态和展开形态，不再沿用 v1.0/v2.0 常驻大宽行设计；消息分类与权限本身仍参考[基础分 Tab 方案](../Hoki｜房间公屏消息分Tab｜产品方案｜v1.0｜可评审版.md)。

| 操作 | 结果 |
|---|---|
| 点击分类条箭头 | 展开/收合分类选项；公屏高度不变 |
| 点击某个 Tab | 切到该分类，不切房间视图、不改公屏大小 |
| 在公屏内横滑 | 切相邻分类；分类条同步当前选中项 |
| 在公屏内纵滑 | 阅读消息，不触发缩放或房间切屏 |
| 点游戏房四角按钮 | 仅变更公屏大小，Tab 与分类条状态保留 |
| 聊天房非公屏区域横滑 | 仅变更房间/整屏视图，当前 Tab 保留 |

一次触摸按起点归属，只执行一个动作。Tab 首尾不循环、不冒泡到房间切屏，是本方案的防冲突实施规则；录屏不能独立确认全部边界行为，不把它写成竞品已验证事实。

布局变化保留草稿、当前分类及各分类阅读锚点；处于底部继续看最新，阅读历史不强制跳底。不因缩放/切屏重播消息、重做进房或礼物业务，也不无条件清除未读点。

键盘、弹窗、长按、系统边缘返回和游戏 SDK 手势沿用原组件优先级；弱网仍可本地切布局/分类。切房取消旧手势及旧房回调。同房从聊天变游戏后回小公屏、从游戏变聊天后回房间视图的状态归一建议保留，需研发评审；不影响本轮已裁决的竞品视觉方案。

## 6. 交付给设计与研发的要求

### 必须按竞品复刻

- 四角展开/收起图标及其位于分类条左侧的关系。
- 分类条“当前项＋箭头”与横向 All / Chat / Gift 两种形态；紫色紧凑容器、选中样式和间距。
- 小公屏透明、展开态局部黑色半透明，保留上部游戏画面亮度。
- 公屏两档的相对位置、出现/收起的过渡结构，聊天房整体横向切换。

### 接入本品时必须一起调整

- 重新排列游戏区的竖向间距，让 Join/Start 等关键控件在小公屏上方完整可见，不沿用旧界面叠加方案。
- 本品房间背景、游戏内容、头像和业务入口继续使用正式资产；不把竞品昵称、房间 ID、消息或活动作为本品业务数据。
- 可见图标按竞品做，可点击范围、安全区、字号放大与 RTL 用原生约束验证；不会因为“按截图复刻”而保留无法点击或热区重叠的问题。

本需求主要改客户端布局和手势，不变更支付、返奖、游戏结算或管理权限。灰度可关闭新增手势并退回发布前布局；回滚方案由研发沿现有发布体系配置，不把已否定的 v2.0 当作本轮默认设计。

沿用已有 `room_public_expand` / `room_public_collapse` key，语义对应新四角按钮；Tab key 沿用基础需求。英文与阿语审校、安全通知、禁言和消息治理仍使用既有流程。
