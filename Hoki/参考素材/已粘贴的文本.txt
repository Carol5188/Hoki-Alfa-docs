## 1. 关系规则与权限

| 兄弟 | 与闺蜜/挚友共用3个免费位，可按既定规则扩至5位；门槛500；双方有可用亲友位 | 不做性别校验 | 选择类型和符合条件的好友，直接发送系统邀请 |
| 闺蜜 | 同上 | 不做性别校验 | 同上 |
| 挚友 | 同上 | 不做性别校验 | 同上 |

+ 同一对象之间最多一种正式关系；新增亲友关系不得覆盖已有CP或其他关系

#### 分场景提示与校验优先级
同次校验返回稳定业务错误码，客户端按码展示对应文案。建议优先级：账号/好友/已有同对象关系或重复申请 → 本人对应位 → 好友对应位 → 亲密度门槛 → 其他关系资格；各Toast相互独立，同一点击只提示优先原因，修正后重新校验其他条件

| 场景 | 触发和处理 | 中文提示 |
| --- | --- | --- |
| 本人亲友位满 | 发起/发送时没有可用位，停在创建前 | 你的亲密关系位已满，无法建立关系 |

| 好友亲密度不足 | 空位、好友关系和其他资格符合，但未达500 | 亲密度不足，还差{value}，暂时无法建立关系 |

#### 双端空位与并发建议
+ 可用亲友位＝已解锁容量−正式关系占用−有效pending占位，最小为0；3个免费位和已购第4/5位共用计算，同一申请在同一账号只占一次，CP独占位不计入
+ 申请、双方占位同时成功才返回发送成功；任一方无位则全部不创建，不发IM，不亮新增申请红点，不单边占位。邀请前不自动扩容或释放别人的申请
+ 两名邀请者争抢同一好友最后一个位时，仅一个创建成功；另一方返回好友位满错误，使用上表指定Toast。重复提交/超时按原请求ID查询，不再占第二席
+ 拒绝/超时释放双方原本申请占位；接受转正式占用，关闭/查看/删IM不释放。旧申请若缺双端预留，在接受时按原子事务补足空位并建立；无法补足就停在pending、展示本人或好友位满，可拒绝或按原截止时间到期，不延长、不自动撤回

## 4. 关系消息列表与详情样式
+ **红点：当前用户存在未读的关系申请消息或关系处理结果消息，不代表业务状态，打开详情并成功加载后，将当前消息版本标记为已读；关闭、同意、拒绝都沿用这个已读结果。若加载失败，则不能清除红点**
    - 关闭详情只代表消息已读，不代表申请被取消、拒绝或接受 申请仍保留“待处理”状态，用户之后可以再次打开
    - 红点按消息卡片或消息事件清除，不按业务状态清除 所以“待处理”状态可以继续存在，但已经读过的卡片不再亮红点
    - 红点消失后，如果申请状态发生新的变化，重新产生一条结果消息并显示红点，例如用户先关闭申请详情，之后对方撤回、过期或系统产生处理结果，就应重新提醒

+ “收到的申请”展示收到的邀请及其结果；“我发出的”展示发出的申请及结果
+ 默认展示收到页；仅有发出申请的新结果时默认进入发出页；两侧都有提醒时优先收到页
+ 收到页优先有效待处理申请，组内按创建时间降序；结束记录在后，按处理/过期时间降序。发出页优先待对方确认，结果记录随后按更新时间降序
+ 卡片统一包含对方头像/昵称、关系类型、申请种类、状态、摘要、截止时间或处理时间、查看入口。最多两行摘要，长昵称省略，时间与按钮不互相挤压
+ 状态文字必须区分“待处理”“等待对方回应”“已接受”“已拒绝”“已过期”。协议解除使用“待确认解除”“已同意解除”“已拒绝解除”“已结束（未同意）”
+ 无消息显示“暂无关系申请”；全部处理完且有记录时保留结果卡，不替换为空态。加载失败显示重试，不显示“暂无”

#### 3、周期、共享与回退
+ 每段关系独立统计，双方共享进度与一次奖励：**每日最多40、每周最多80**。任一方完成单方可满足的任务即推进双方同一实例；双人条件仍须双方各自达标。双方页面各显示同一奖励，不发成两份
+ 刷新时区沿用当前关系分区：每日00:00、每周日00:00；建立后开始统计，不补算建立前互动。不同自然日按该关系同一时区去重，刷新/换设备/一方补填性别不重置周期或进度
+ 同一行为可推进多个合格任务及多段合格关系，每段按关系和任务实例独立去重，不分摊时长；礼物子单只推进对应收礼对象的关系。基础行为成长与任务奖励分来源，奖励入当前关系现行成长账户，不新增账户或等级算法
+ 背包、免费、运营赠送、全额券、失败订单不计送礼任务；部分抵扣后确有金币实付且订单合格可计。求婚戒指及升级戒指均计入日“送份礼物”或周“关系升温”。BOND/CP固定成长值只入一次，不叠加普通礼物比例
+ 周期结束时未完成目标过期；已完成但奖励延迟按原实例补记。新周期重新生成8条当期任务，不把上周期完成态、按钮禁用态或计数带入新周期
