## 1. 目标与当前结论

让用户区分「手动点击」「按住连击」「自动连击」，在连续送礼时持续看到已确认结果和私有余额，并能明确停止。公屏、公共送礼横幅、飘屏和方形返奖动效使用同一份已确认结果，避免重复、错奖与金额混淆。

本期采用：**自动模式点击先确认，再发送首笔；长按模式按住满 2 秒，经 boom 反馈后连续送礼，松手即停。** 两种连续模式互斥，自动模式优先。速率只在后台配置 1—5 次/秒，默认演示为 2 次/秒；客户端没有速率选择器。自动连击不设次数或强制时长上限，离开可交互房间立即阻断后续发送，返回不自动恢复。

本期改展示与送礼控制，沿用现网概率、单价、数量计算、返奖入账、账户权限和财务结算。新接口字段为接入建议，须映射现网契约。

## 4. 范围、角色与权限

### 4.1 范围

本期：幸运礼物三类公共反馈及方形动效、送礼者本地余额、Combo Setting、自动/长按控制、后台独立开关和速率、异常停止与多语言。

幸运礼物以外的支持连击礼物可复用控制能力，但返奖展示只消费真实返奖结果。不支持连击的礼物维持原送礼流程；自赠、运营赠送、多人/多数量组合均按现网资格，不能因开关绕过限制。原型演示「每次 1 个、一个收礼人」，未新增全麦、多收礼人或批量支付规则。

## 5. 设置入口与用户偏好

1. 房间右上工具 → Basic Tools → **Combo Setting**，替代原 Combo Skin 名称。
2. 设置页包含 **Auto Combo**，用户默认关闭；以及 **Combo Skin Setting**，跳转原有皮肤选择页。
3. 开启 Auto Combo 只保存使用偏好，不发首笔、不扣费、不自动开始；关闭时立即停止本人的自动会话。
4. 皮肤选中、应用与返回沿用原页权益/购买校验；返回 Combo Setting，不能改动 Auto Combo 或启动送礼。
5. 后台自动能力关闭时隐藏用户 Auto Combo 行，保留皮肤行；已存用户偏好不删除，但不生效。能力恢复后可显示原偏好，必须再次主动启动，不恢复旧会话。
6. 建议用户偏好按账号保存；换号隔离。服务端/本地持久化实现及多端同步待接入；存储失败应反馈，不误称跨端已保存。
7. 打开工具、设置、皮肤、收起礼物面板等会遮挡主要操作的行为先停止连续送礼。回来后保持停止。

## 6. 三模式真值表与优先级

定义 A＝后台自动能力；H＝后台长按能力；U＝用户 Auto Combo 偏好。有效自动＝A∧U；有效长按＝H∧¬(A∧U)。资格、前台及送礼权限仍是共同前置条件。

| A | H | U | 点击 Combo | 按住满 2 秒 |
|---|---|---|---|---|
| 关 | 关 | 任意 | 手动发送 1 次 | 不启动连续；已识别为长按的手势松开不补发 |
| 关 | 开 | 任意 | 手动发送 1 次 | 长按模式，松手停止 |
| 开 | 关 | 关 | 手动发送 1 次 | 不启动连续 |
| 开 | 开 | 关 | 手动发送 1 次 | 长按模式，松手停止 |
| 开 | 关或开 | 开 | 新轮按提醒资格确认后启动自动 | 不启动长按模式，不绕过自动确认 |

自动运行时点击原按钮直接停止；长按运行中松手停止。不能把一次手势同时解释为单次发送和连续启动。礼物选中不发送，礼物价格或收礼人变化要结束旧轮，重新确认新上下文。

### 6.1 手动模式

短点击发送一笔。成功后更新 Combo 和钱包，失败不提前计为成功；有在途时禁用下一次提交。原型手动聚合窗口为 5 秒示意，正式窗口沿用现网，未将 5 秒写为新业务规则。

### 6.2 自动模式与确认弹窗

当有效自动开启，用户主动点击 Combo 新一轮，且没有当天有效免提醒记录时，展示附件式弹窗。弹窗开启时尚无首笔请求。

```text
Auto Combo                                      ×
是否开启自动连击？开启后连续送出当前礼物，
点击 Stop Auto Combo 按钮可停止。
当前礼物 → 收礼人
每次 X 金币 · 余额 Y 金币
你可以随时点击停止；余额不足、最小化或退出房间、
切换 App 或锁屏时自动停止，返回后不会自动恢复。
□ 我已知晓，今日不再弹出确认提醒
[仅发送一次]                     [开启自动连击]
```

| 操作 | 是否发送 | 免提醒记录 |
|---|---|---|
| × / 返回 / 支持的遮罩关闭 | 不发送 | 不写入，临时勾选清空 |
| 仅发送一次，勾选与否均同 | 仅发一笔手动请求 | 不写入；用户 Auto Combo 偏好可保留 |
| 未勾选＋开启 | 校验通过后启动本轮自动 | 不写入，下轮仍提示 |
| 勾选＋开启 | 校验通过后启动本轮自动 | 保存本账号当日偏好 |
| 已有当日免提醒，主动点击 Combo | 直接启动新自动轮 | 按钮辅助文字为“今日免提醒 · 点击即启动” |
| 弹窗期间切后台/离房/礼物资格变化 | 关闭且不发送 | 不保存当前勾选 |

免提醒只减少重复提示，不能替代下一轮的主动启动。只切开关、进入房间、恢复 App、配置恢复都不启动。运行中点击是停止操作，不弹启动确认。跨日连续会话不插入弹窗，也不强制终止；下一轮主动点击重新判断日期。正式日期使用服务端明确的业务时区/日界线，原型使用本机自然日并提供“模拟次日”。

确认后、请求前再次校验房间、礼物、收礼人、单价/数量、余额和能力版本；弹窗期间上下文失效则关闭，不能静默转送其他礼物或对象。免提醒写入时机为校验通过且接受启动意图，不以返奖发生作为条件。

### 6.3 长按模式

仅有效长按开启时生效：按下 → 2 秒进度 → 一次 boom 反馈 → 保持按住期间按配置节奏发送。松手、滑出按钮、系统取消、捕获丢失、页面失焦或资格失效立即锁停止。2 秒阈值前取消不发首笔；已经识别成长按的手势松开不补发单次。

正常短点击仍走手动一次。原型用 300ms 区分短点击与已识别长按取消，仅用于交互演示，原生手势识别阈值须与客户端控件统一；2 秒启动阈值按本方案。boom 原型约 350ms 后首笔，仅作时序示意：boom 期间松手须零发送。

长按不需要自动确认弹窗，不写当日免提醒；用户必须持续按住。自动模式有效时，长按取消不能绕过确认或启用第二种模式。所有皮肤都须有进度、boom 和停止/松手提示，皮肤不覆盖功能语义。

## 7. 状态机、停止与回执

| 状态 | 进入条件 | 出口 / 可操作 |
|---|---|---|
| ready | 前台可操作，无未结请求 | 短点击进入 single/confirming；有效长按进入 pressing |
| confirming | 新自动轮需要提醒 | 关闭→ready；仅一次→single；确认→running_auto |
| pressing | 有效长按，未满 2 秒 | 取消→ready 且不发；达阈值→arming |
| arming | boom 启动中，仍按住 | 保持→running_hold；松手/中断→ready，无首笔则零扣费 |
| single | 单次在途 | 成功/明确失败→ready；未知→blocked 核实 |
| running_auto | 已接受自动启动 | 点击停止或中断→stopping；松手不停止 |
| running_hold | 按住连续模式 | 松手/滑出/取消或中断→stopping |
| stopping | 已锁禁止后续请求 | 无在途→ready/suspended；有在途等待结果，不可再启一轮 |
| blocked | 请求结果未知/资格未恢复 | 核实、刷新权限或配置后可主动重试；不自动续发 |
| suspended | 非完整前台房间 | 回来只同步结果→ready/blocked；不恢复连续会话 |

### 7.1 统一停止算法

先写本轮停止锁，再取消长按进度、boom 和下一笔定时任务。停止是幂等操作。原 Combo 按钮自动模式下变为 **Stop Auto Combo / 已确认 N 下**；有旧在途时显示 **停止中… / 等待已发请求确认**，收口后恢复准备态。按钮可使用有限加载状态，不能长期失去明确结果。

停止不能撤销已经发往服务端的那一笔。停止后成功回执仍正常记账、更新确认次数及钱包；回调检查停止锁、会话 ID、房间上下文，绝不能排下一笔。无新绿色状态条、无结束汇总卡。运行统计只用于后台日志或右侧原型评审区。

### 7.2 串行与速率

| 后台次数/秒 | 发起周期 |
|---|---|
| 1 | 1000ms |
| 2 | 500ms |
| 3 | 约 333.33ms |
| 4 | 250ms |
| 5 | 200ms |

每轮启动时固定配置快照。以相邻请求**发起**时间间隔调度，不能在每次回执后再完整等待一个周期造成无意减速。全轮最多一个在途；下一笔同时满足前笔已明确完成、距上笔发起已达周期、仍有资格、仍处前台可交互、未停止、模式仍有效。慢回执自然降速，不积压、不追发、不并发。后台目标速率不保证网络下的实际成功速率，不绕过服务端限频。

速率更新下一轮采用；当前能力被关立即停止对应模式，不切换到另一模式继续刷。1—5 次/秒需正式服务端承载与限频验收，原型普通回执 80ms、慢回执 3 秒仅为测试参数。

### 7.3 生命周期停止矩阵

| 触发 | 本轮处理 | 返回或恢复 |
|---|---|---|
| 点击 Stop Auto Combo、关闭用户开关 | 阻断后续，旧在途结算 | 用户再次主动启动 |
| 长按松手、滑出、取消、失捕获 | 停止长按模式 | 再次完整按住 2 秒 |
| 最小化/小窗/悬浮房间、退出/切房 | 停止；旧房回执不污染新房展示 | 不续发 |
| 切 App、系统后台、锁屏、电话/系统中断、不可交互 | 停止；钱包核实保留 | 不续发，不补播过期大动效 |
| 打开工具/设置/皮肤、收起面板、全屏遮挡 | 先停止，保护原位停止按钮可达性 | 返回仍停止 |
| 切礼物/收礼人/数量、币种/价格变化 | 结束旧上下文；不把新参数塞进旧轮 | 新轮校验及提醒 |
| 断网、明确失败、余额不足、权限撤销、礼物下架、踢出、关房 | 停止，不自动重试扣费 | 原因消除后主动启动 |
| 结果超时未知 | 停止并核实原请求，禁止第二笔 | 核实收口后主动启动 |
| 后台关闭正在用的能力 | 立即停止该模式 | 即使另一个能力可用也不自动切换 |

浏览器用 visibility、blur、pagehide 及模拟按钮验证；iOS/Android 必须接原生生命周期、系统中断、浮窗状态。纯 JS 定时器不构成线上完整保护。

| 字段 | 用途与约束 |
|---|---|
| request_id / idempotency_key | 一笔送礼唯一；超时核实/重复提交沿用同一键，不再创建扣费 |
| combo_session_id、combo_mode | manual / hold / auto；关联停止原因和本轮上下文 |
| room_id、sender_id、recipient_ids、gift_id、quantity | 固定本轮语义；单笔数量与现网支付金额对应 |
| unit_price、currency、config_version | 服务器校验后的费用与配置，禁止静默涨价续发 |
| result_status、result_version / sequence | 成功、失败、未知及后续修正，支撑乱序处理 |
| reward_result_id | 同一返奖在各层一致；公共广播重复时按 ID 幂等 |
| combo_count_confirmed | 仅成功确认计数；不能按点击、进度或发起数先加 |
| reward_type | 金币返奖 / 倍率返奖，映射现网枚举，不创造新玩法类型 |
| reward_coins_current、multiplier | 当前结果金额与服务端倍率；不能自行用礼物单价反算 |
| reward_tier、effect_resource_id | 已有低中高等级及对应资源；不在客户端定义金额阈值 |
| balance_after、wallet_sequence | 私有钱包快照及顺序，金额格式/取整沿用现网；禁止进公共广播 |
| reversal_of / corrected_version | 撤销、退款、补偿等现网修正关联；不能重复播为新中奖 |

原型按顺序 mock 回执，只做本地模拟扣费；模拟返奖独立展示，不加入模拟余额。正式余额必须直接使用服务端 wallet snapshot，不按本地减价或叠加返奖推算；不能用原型样例金额反推倍率、概率或账务公式。

### 8.2 公屏消息两类模板

- 金币返奖：`[头像] 昵称 送出 [礼物]，获得 {reward_coins} 金币`，突出金额，不附无来源倍率。
- 倍率返奖：`[头像] 昵称 送出 [礼物]，返奖 ×{multiplier}，获得 {reward_coins} 金币`，倍率和金额都来自本次票据。
- 零返奖仅保留普通送礼成功消息，不使用中奖/获得正数返奖文案。
- `Combo ×N` 代表已确认送礼次数；`返奖 ×M` 代表倍率，两处标签不得混用。
- 同一 `reward_result_id` 重复回调更新或忽略同一行，不能重复新增；不同有效结果不能因为同人同礼物而被误去重。多条合并展示若沿用现网，必须可追溯明细，不把当前金额写成累计。
- 撤销/补偿按现网修正协议更新记录与私有钱包，禁止播放新的中奖动效；若当前协议缺失，列为接口评审阻塞项。

### 8.3 公共送礼横幅

全房间可见，展示头像/昵称→收礼人、礼物、**COMBO ×已确认次数、当前已确认返奖**。公共横幅无余额、用户开关或停止控件。当前返奖是本笔，不是本轮累计。

同一有效 Combo 实例更新一个横幅，不每笔堆一条；不同用户沿用现网调度，不能覆盖成同一人的累计。停止后的旧在途成功允许更新本轮最终确认结果，但不能启动新请求。横幅消失窗口沿用现网；原型保留最后一条便于评审，非正式持续时长承诺。

### 8.4 飘屏、方形返奖动效与拥塞

低级复用通用轻量表现；中高级按服务端等级使用现有尺寸/安全区内的高亮飘屏。方形返奖容器、占位和回调保持，金币主数字 `+金额`，倍率主数字 `×倍率`；完整金额仍可在公屏/横幅查看。

公屏记录保真；横幅更新当前结果；飘屏与动效属于氛围层，可依现网频控更新、排队或降级，不能因丢弃动画丢失真实结果。不遮住停止按钮、返回入口、麦位关键操作。资源加载失败用通用方形/文本回退，不阻塞停止和送礼回执。切后台/切房后不补播旧大动效。

正式时长、队列长度、优先级与节流阈值引用现网规范，缺失时需设计/客户端补齐；原型每层单实例、约 1.1 秒动效/1.6 秒飘屏仅为示意。`*2` 的资源数与等级映射是设计交付缺口，不能自行升级为四套。

## 9. 后台连击配置

入口沿用后台礼物配置区的「连击设置」弹窗。原型右侧可打开同款配置，默认演示分区为「锋哥大区」；并不代表已确认所有后台配置粒度。

| 字段 / key | 类型、值域 | 含义 |
|---|---|---|
| 自动连击 / auto_combo_enabled | Boolean | 是否开放用户 Auto Combo 能力；与长按独立 |
| 长按连击 / hold_combo_enabled | Boolean | 是否支持用户按住满 2 秒连续发送；与自动独立 |
| 连击速率 / combo_rate_per_second | Integer 1/2/3/4/5 | 两连续模式共用；默认演示 2，正式灰度初始值在发布单记录 |

- 两开关均关时速率置灰并保留原值；只要其中一个开，速率可改。不能关自动就连带禁用长按。
- 无用户权限、区域、礼物或客户端版本资格时，开关不绕过服务端校验。
- 离开房间即停、返回不恢复、单在途和停止锁属于固定保护，后台不提供关闭保护的配置。
- 保存按钮校验整数枚举、权限、配置版本；提交中防重复。保存成功回填已保存值；取消/×/Esc 有修改时询问继续编辑或放弃。保存失败保留草稿、原配置不变，可重试。
- 正式保存需记录区域/适用礼物范围、前后值、操作人、时间、备注/审批（沿用现有制度）、配置版本和生效结果。并发编辑冲突提示刷新，不能静默覆盖他人配置。
- 配置下发必须可撤销：能力关闭使对应在线会话阻断下一笔；速率变更新轮生效。旧客户端仍走原手动能力，不能误把不支持的字段当自动开启。
- 原型仅本地配置持久化；权限、审计、发布、跨端推送和并发冲突均未接。

## 10. 异常与资格闭环

| 场景 | 用户看到 / 系统处理 |
|---|---|
| 余额不足 | 连续停止，给现网余额不足提示；不自动充值、不恢复连击 |
| 明确网络失败 / 服务端拒绝 | 停止，按明确未受理结果处理；不增加确认次数；是否扣费以权威状态为准 |
| 超时、未知、断线重连 | 核实原请求及钱包，禁止换键盲重试；查到成功才展示，失败才释放；不自动续发 |
| 重复结果 / 双通道广播 | 结果 ID 去重；本地余额按钱包顺序，不重复扣费与返奖播报 |
| 乱序钱包或结果修正 | 钱包只接受更新序列；相同票据更高版本才修正；公屏与动画避免倒退 |
| 跨房旧回执 | 原送礼正常收口；钱包可同步；旧房公共结果不可塞入新房，不能续发 |
| 价格、币种、数量或对象变化 | 停旧轮，重新展示费用/对象；不能无感沿用旧授权 |
| 礼物下架、踢出、禁送、关房 | 服务端拒绝后停止，清除不再有效的本轮资格；恢复需主动操作 |
| 皮肤不可用/资源失败 | 回退默认功能按钮；停止语义、进度与余额可见 |
| 弱机/动效关闭 | 保留文本与可操作停止；氛围层降级不影响账务和结果记录 |
| 换号 / 多端 | 结束本机旧会话，用户偏好与免提醒按账号隔离；服务端沿用账户并发支付校验 |

不新增独立处罚、设备/IP 关联封禁或奖励补发规则。客服查询提供“用户主动启动→请求发起→停止锁时点→在途结果→钱包序列”的证据链；停止后到账的一笔可解释为停止前已发出，停止后新请求数应为 0。对用户展示通用失败原因，不披露风控因子。

## 13. 上线、灰度与回滚

先对支持能力版本、指定分区和礼物灰度；正式默认能力开关及灰度名单写入发布单，用户偏好默认关闭。验证1—5档承载、iOS/Android 生命周期、钱包幂等/核实/修正及服务端停止边界后再扩量。旧版本保留手动送礼。

回滚分别关闭自动或长按能力；在用该能力的客户端收到变更后停止新请求，已受理请求正常结算。必要时服务端拒绝新的连续请求，已受理单据不丢失；不回滚财务流水、不把旧会话恢复。配置版本、审计与监测可追溯。原型打开后台会先停止以免演示遮挡；不能据此声称已验证线上实时推送。

## 14. 验收清单

1. 工具入口改名、用户开关默认关、皮肤跳转返回；切开关或换皮肤不发送。
2. 真值表全部成立，后台自动关＋长按开可按住；有效自动开时不能绕过确认长按启动。
3. 首笔确认前零请求；×零发送；仅一次恰一笔且不保存免提醒；勾选＋确认后当日新轮免提醒。
4. 模拟次日下轮再弹，运行跨日不插窗；换号/重启不会错误继承他人偏好。
5. 长按不足 2 秒取消无连续/无补发；boom 前松手零发送；保持按住发送、松手/滑出/取消停止。
6. 自动运行原位 Stop Auto Combo 可随时点，皮肤不覆盖；删除的绿色条与汇总卡始终不存在。
7. 在途停止仅旧笔结算，回执不续发；未知请求核实前不能开第二笔；无次数或强制时长上限。
8. 每个生命周期停止场景在两原生端实机验证，返回不续送，旧房结果不污染新房。
9. 1—5 档保存回填，速率新轮快照；单在途、慢回执降速、不补发；配置能力关闭即时停止对应轮。
10. 金币/倍率两类模板正确，COMBO 与倍率分开；0奖无中奖文案；跨通道去重/乱序/撤销按契约处理。
11. 横幅全房可见，余额/设置/停止仅本人可见；公屏、横幅、飘屏、方形动效对应同一票据。
12. 余额不足/断网/权限拒绝/资源失败闭环；后台失败保留草稿、取消不发布、并发冲突和权限有服务端校验。
13. 390px 布局、RTL、长阿语、读屏/返回/键盘操作、弱机动效降级均不遮挡停止。
14. 用真实账户测试环境核对钱包、扣费、返奖流水和停止证据链；原型成功不能代替正式验收。
