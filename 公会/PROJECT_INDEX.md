# 公会项目索引

更新时间：2026-08-25

## 当前定位

本目录沉淀公会业务的长期背景，覆盖用户端建会与成员管理、运营后台治理、数据看板、业绩与工资结算，以及等级、榜单、荣誉和公会活动。

本模块与 ACM/BD 模块并列维护：公会是独立的经营和用户关系业务域；ACM V3 用于外部拓展团队的组织、权限、额度和公会直接归属治理；BD 通常是 ACM 团队中承担公会拓展职责的成员或层级，不能与旧 BD 系统或公会长身份直接等同。

GitHub 当前目录：<https://github.com/Carol5188/Hoki-Alfa-docs/tree/main/%E5%85%AC%E4%BC%9A>。

## 当前口径

- 公会、用户、主播、成员、公会长、管理员、运营、财务、ACM 与 BD 是不同主体或角色；功能权限、数据可见范围、后台管理范围和报表范围必须分别判断。
- 公会关系、成员关系、直接归属、统计周期和配置版本共同决定业绩、工资、榜单和历史查询结果；不能只根据当前页面或当前团队树推断。
- 业务日和周期以页面标注的 UTC+3 为准。当前周期结果可以刷新或预估，已结束/结算的历史周期必须以当期冻结结果为准。
- 同一大区存在公会数据，不代表该大区自动支持所有看板列、工资、等级、活动或 PK 能力；以目标大区的当前有效配置和统计链路为准。
- 创建、转移、冻结、删除、配置发布、结算补跑、奖励发放和赛事晋级均可能影响多域数据，需按高风险流程执行，不得通过重复提交、删除重建或重跑成功对象绕过异常。

## 历史/参考边界

- 文档所述 V1/V2、旧 BD、历史报表和旧页面仅用于兼容、追溯或迁移判断，不能作为新需求的默认现行方案。
- 附件中的“关联章节”保留了原知识库的编号路径；本目录以本索引的八份文件为有效导航，不假设原编号链接在仓库内可用。
- 原始附件保持原文，不在其中混入新需求结论。新旧口径冲突时，先在具体需求文档中列出冲突裁决表，再修改当前版产物。
