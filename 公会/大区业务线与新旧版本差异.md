# 大区业务线与新旧版本差异

最后核验日期：2026-08-19

## 适用人群

面向处理跨大区需求、ALFA、ACM V3、BD 存量报表、旧客户端兼容和系统迁移问题的产品、运营、数据与财务人员。

## 功能说明

公会基础身份在多个大区和应用中复用，但数据指标、结算周期、工资政策、活动能力和后台页面并不完全相同。本篇先说明当前应使用的能力，再集中列出旧版和兼容边界。

## Hoki 主线大区差异

### ARAB

ARAB 是最早且能力最完整的公会主线，常见能力包括：

+ 公会主页、成员、申请和邀请。
+ 公会及主播日/半月数据。
+ 主播和公会工资、余额工资、预支工资。
+ 等级、升级资源、最强公会、荣誉、铭牌和 PK。
+ 统一结算、运营报表和 ACM 半月工资看板。
  历史功能大量从 ARAB 演进。把能力扩展到新区时，不能只确认页面存在，还要确认新区的数据、配置、任务和奖励链路均已接通。
  
  ### PHL
  
  PHL 使用钻石有效业绩，拥有专门的公会和主播区域报表、日榜和导出。工资周期可能按周或半月配置，因此产品和运营不能把所有 PHL 页面写死为半月。
  PHL 的 ACM 看板突出新老公会分段工资和 BD 维度汇总。存量 BD 半月快照和后台报表仍保留，用于区域经营和历史对账。
  
  ### SASIA
  
  SASIA 使用钻石有效业绩，支持专门的公会和主播报表、统一结算，以及 BD 业绩记录与汇总报表。跨区绑定会被过滤，BD 与公会必须保持同区。
  
  ### AFRICA
  
  AFRICA 支持公会和主播区域报表、日榜、导出、统一数据看板和正式周期结算。个人看板按钻石工资型指标展示。
  AFRICA 的历史实现曾有独立汇总路径。当前产品验收应优先对照统一数据和成功汇总，不引用旧表口径。
  
  ### MENA
  
  MENA 已纳入标准运营大区、统一数据查询和主播个人看板。个人看板按钻石工资型指标展示，但当前统一正式结算范围不包含 MENA。
  涉及 MENA 工资、预支、等级或活动上线时，必须逐项确认能力是否已开放，不能因为看板有数据就默认结算完整。
  
  ### TR 与 CIS
  
  TR 和 CIS 主要使用红钻/宝石经营口径，常见周期为月。公会和主播后台报表展示宝石收入及相关结算收益；ACM 看板采用月度礼物流水视角。
  这两个大区当前不走钻石型统一正式结算。页面出现即时宝石和次日宝石时，应分别展示，不把二者合并成钻石工资。
  
  ## ALFA 业务线
  
  ### 与 Hoki 的关系
  
  ALFA 复用部分公会身份、成员和运营能力，但拥有独立的数据、结算和管理工资政策。Hoki 与 ALFA 的运行环境和配置相互独立，同为 ARAB 大区也可能得到不同页面和工资结果。
  
  ### 用户可见能力
  
  ALFA 公会和主播页面支持按日及业务周期查看经营数据。公会页展示公会统计，主播页展示个人资料和对应统计。
  部分 ALFA 大区不展示通用公会首页。例如 ALFA 的 PHL 场景当前不会开放通用公会页，不能用 Hoki PHL 的入口逻辑推断。
  
  ### 运营后台
  
  ALFA 后台提供：
+ 公会数据看板和主播数据看板。
+ 按日或周期筛选。
+ 按公会、主播或关联管理账号查询。
+ 公会、主播和管理视角导出。
+ 周期经营汇总和公会列表。
  ALFA 报表与 Hoki 主线报表不能混用。导出前要确认当前应用和页面标题。
  
  ### 日数据与周期数据
  
  后台会持续归集 ALFA 公会和主播的日数据，并生成周期数据。统计内容包括钻石、金币、礼物、上麦时长和有效上麦天数等，具体展示由页面和政策决定。
  日数据与周期数据可能分批刷新，用户端短暂不一致时先核对刷新时间和统计状态。
  
  ### 半月结算
  
  ALFA 有独立的半月结算流程，负责统计目标半月、处理主播余额并保存结算结果。该流程和 Hoki 通用结算使用相同的安全原则，但业务副作用不完全相同：
+ ALFA 使用自己的工资和余额处理口径。
+ 不默认包含 Hoki 主线的主播业绩奖励、公会等级更新和升级通知。
+ 成功、失败和部分失败仍需按公会、主播和金额核对。
  同一周期不得让 ALFA 旧结算和其他结算链路并行处理同一范围。
  周期结束并完成处理后，上一周期的财务结果会作为历史记录留档，供运营和财务查询、对账。留档结果用于追溯当期处理，不应被当前周期的归属或政策变化覆盖。
  
  ### AR 月度分层工资
  
  ALFA 的 AR 月度管理工资把两个半月的公会工资合并为自然月，再按 ACM 层级计算。
  
  | 角色                                                          | 工资范围            | 工资组成                |
  | ----------------------------------------------------------- | --------------- | ------------------- |
  | Manager（管理者）                                                | 自己及全部下级管理范围内的公会 | 团队总工资档位底薪、新公会奖励     |
  | 超管                                                          | 自己及全部下级管理范围内的公会 | 团队总工资档位底薪、新公会奖励     |
  | BD                                                          | 直属公会            | 新公会固定奖励、不同月龄公会的比例工资 |
  | 更低执行层级                                                      | 自身不生成管理工资头      | 其公会继续计入符合条件的上级范围    |
  | 当前月为预估，可混合使用已经正式完成的半月结果和仍在进行中的半月预估；历史月必须具备完整的上下半月成功结果后才能冻结。 |                 |                     |
  | 同一公会可以进入不同上级角色的工资基数，所以不能把所有管理账号工资头简单相加解释为公会物理总工资。           |                 |                     |
  
  ## ACM V3 现行体系
  
  ### 定位
  
  ACM V3 是当前外管体系，负责：
+ 外管账号层级和团队结构。
+ 用户账号与外管账号的绑定。
+ 成员和公会的直接归属。
+ 功能权限和菜单。
+ 团队额度。
+ 数据看板、历史记录和周期工资。
+ 后台结构治理、报表和异常审计。
  BD 在部分模板中仍是角色名称，但旧 BD 身份和旧 BD 关系不再是现行运行时的权威来源。
  
  ### 入口与菜单
  
  外管账号可以拥有成员工作台入口、管理中心入口或两者之一。入口权限彼此独立；账号仍可能保留兼容地址，但是否显示入口由现行权限决定。
  工作台菜单由账号模板、层级、最终权限和应用共同决定，常见入口包括：
+ 工作台。
+ 数据看板。
+ 成员管理。
+ 公会管理。
+ 当前记录和历史记录。
+ 新增成员和创建公会。
  普通非 ACM 用户不会获得这些入口。
  
  ### 成员管理
  
  有权限的账号可以：
+ 分页查看允许范围内的外管成员。
+ 精确搜索可创建为成员的用户。
+ 检查用户是否符合创建资格。
+ 选择模板允许的下级角色并创建成员。
+ 调整直属上级。
+ 删除符合条件的成员。
  新增成员受到三层限制：当前账号权限、模板允许创建的下级层级、顶级团队共享额度。页面允许提交不代表服务端一定放行，最终以提交时复核为准。
  
  ### 公会归属
  
  公会可以直接归属某个有效外管账号。现行能力包括：
+ 查看未分配公会。
+ 搜索可作为直接归属的账号。
+ 分配公会。
+ 转移公会直接归属。
+ 批量转移公会。
+ 由有权限的外管账号创建直属公会。
  当前周期通常读取实时归属；历史周期读取冻结归属。公会转移不会重写历史工资。
  
  ### 工作台用户能力
  
  工作台支持精确搜索用户，并在具备权限时修正用户国家信息。国家修改可能影响大区判断和后续可操作范围，必须有明确业务依据。
  
  ### 团队额度
  
  新增成员、创建公会及其他适用动作可以共享顶级团队额度。额度规则来自模板默认值和单个顶级团队覆盖值。
  
  | 状态                                                                 | 含义                  |
  | ------------------------------------------------------------------ | ------------------- |
  | 未启用额度                                                              | 该动作不按数量限制，不应因显示零而阻断 |
  | 有剩余额度                                                              | 可继续提交，提交时再次校验并扣减    |
  | 额度用尽                                                               | 页面阻止操作，服务端也会拒绝      |
  | 额度在顶级团队内共享，不是每个成员独立拥有。运营后台治理动作和 H5 业务动作的额度边界不同，不能用后台调整结果推断用户端已扣额度。 |                     |
  
  ### 数据看板
  
  ACM V3 数据看板提供：
+ 当前账号汇总。
+ 公会明细分页。
+ 直属下级汇总。
+ 历史周期汇总。
+ 按当前账号或允许的下级账号下钻。
+ 当前记录与历史记录。
  常见看板模式：
  
  | 业务场景                                                                           | 周期  | 主要展示                |
  | ------------------------------------------------------------------------------ | --- | ------------------- |
  | Hoki 钻石工资型大区                                                                   | 半月  | 公会业绩、主播和公会工资、管理范围汇总 |
  | PHL 分段工资                                                                       | 半月  | 新老公会分段、BD 和 ACM 工资  |
  | TR/CIS 宝石经营                                                                    | 月   | 公会月度宝石经营数据          |
  | ALFA AR 分层工资                                                                   | 月   | 层级工资头、公会工资和月龄组成     |
  | 当前周期数据可以随实时归属和业绩变化；历史周期必须使用冻结归属和快照。查看下级时，页面必须保持同一个目标成员上下文，不能把登录人汇总和下级公会列表混在一起。 |     |                     |
  
  ### 数据范围与功能权限
  
  功能权限决定能不能执行某类动作，数据范围决定能看到哪些团队、账号和公会。两者互不替代：
+ 有管理按钮但无全局数据范围，只能操作自己可见的团队。
+ 有全局查询范围但无动作权限，只能查看，不能提交治理。
+ 下级账号的最终权限不能突破上级和模板允许范围。
+ 单个账号可以在模板默认权限上增加或禁止允许范围内的能力。
  
  ### 后台账号治理
  
  运营后台提供以下现行治理能力：
  
  | 治理域                                                                                     | 能力                              |
  | --------------------------------------------------------------------------------------- | ------------------------------- |
  | 顶级团队                                                                                    | 创建顶级 ACM、切换模板、配置平级运营负责人         |
  | 成员结构                                                                                    | 创建成员、同团队换绑上级、跨团队迁移、批量迁移         |
  | 层级变化                                                                                    | 成员升为顶级、顶级加入其他团队、调整成员层级          |
  | 账号状态                                                                                    | 禁用、恢复、删除非顶级账号                   |
  | 账号绑定                                                                                    | 绑定或替换用户、搜索可绑定用户、当前后台账号加入 ACM    |
  | 公会治理                                                                                    | 查看账号公会、创建、绑定、转移和批量转移公会          |
  | 模板                                                                                      | 新增、查看、预览影响、保存和删除未使用自定义模板        |
  | 权限                                                                                      | 设置模板默认权限和单账号权限例外                |
  | 额度                                                                                      | 配置模板默认额度、顶级团队专属额度、预览并重置用量       |
  | 异常治理                                                                                    | 查看待修复账号、游离账号、预览修复或游离、查看操作记录     |
  | 奖励库存                                                                                    | 查看指定账号奖励包库存并批量下发                |
  | 报表                                                                                      | 周期归属与业绩、ALFA 月度工资、公会明细、异常、汇总和导出 |
  | 禁用、恢复、结构调整、迁移、层级变化、修复和删除均应先预览。预览必须展示受影响成员、公会、权限、额度和历史快照风险；提交时系统会再次校验，预览成功不保证过一段时间后仍可提交。 |                                 |
  
  ### 运营归属
  
  顶级 ACM 可以绑定一个或多个平级运营负责人。该关系只决定后台治理数据范围，不代表公会业务工资唯一归属。解除运营负责人不会删除 ACM 团队，也不会改写历史周期。
  
  ### 周期报表
  
  ACM V3 后台报表统一覆盖多种大区政策，可查看外管成员、直接归属公会、周期业绩、工资组成和异常数据，并支持汇总与明细导出。
  报表筛选和导出按独立报表数据范围控制，不自动继承结构治理的全局范围。没有报表全局权限时，只能查看当前后台账号负责或自身所属的团队。
  
  ## 现存 BD 报表
  
  旧 BD 用户中心已经退役，但以下后台经营结果仍有业务用途：
  
  | 报表                                                                  | 当前用途                     |
  | ------------------------------------------------------------------- | ------------------------ |
  | ARAB BD 业绩记录和汇总                                                     | 查看半月公会业绩、新老公会及工资相关汇总     |
  | SASIA BD 业绩记录和汇总                                                    | 查看 SASIA 半月经营数据与导出       |
  | PHL BD 半月报表                                                         | 查看 PHL BD 旗下公会业绩、分段汇总与导出 |
  | TR/CIS BD 月度宝石报表                                                    | 查看 BD 旗下公会月度宝石经营快照       |
  | 这些报表依赖上游公会汇总和当前有效归属生成快照。实际是否按计划刷新要以当前调度和运行记录为准，不能因为页面存在就假设数据一定是最新的。 |                          |
  | 新产品需求优先使用 ACM V3 的统一成员、归属和周期报表。存量 BD 报表主要用于区域运营和历史对账，不再扩展成新的独立用户体系。 |                          |
  
  ## V1/V2 与旧入口状态
  
  ### 公会基础功能
  
  公会资料、成员、建会、加入、离会等基础流程仍由长期存在的公会能力承载，没有因为数据页面升级而整体替换。
  
  ### 数据页面
  
  当前推荐使用新版公会和主播数据能力，原因包括：
+ 按大区自动选择展示指标和周期。
+ 支持按日期查询历史日和历史周期。
+ 提供明确的刷新时间。
+ 公会和主播排行使用统一汇总。
+ 支持者和明细支持日/周期范围。
  旧统计页面仍被部分客户端和预支工资记录页面使用，因此不能直接下线。产品新增数据能力应优先接入新版口径；旧页面只做必要兼容和存量维护。
  
  ### 公会主页与成员页
  
  新版主页增加公告、排名展示设置、当前统一业绩和分页成员。旧主页和旧成员列表仍可能被旧客户端调用，出现差异时以当前客户端实际入口和新版业务口径为准。
  
  ### 旧 BD 用户入口
  
  旧 BD 独立用户端入口已于 2026-07-15 的 ACM V3 全量切换中移除。原有部分 H5 路径保留为兼容跳转或数据中心壳，但成员创建、公会归属和数据看板的权威能力已经迁移到 ACM V3。
  不能再按旧 BD 身份、旧绑定关系或旧页面设计新流程。
  
  ### 旧 BD 与 ACM 汇总链路
  
  旧 ACM 工资汇总和部分无消费者的旧汇总任务已经退役。仍有读方的区域快照和后台报表继续保留。运营如发现同一周期新旧任务同时产出结果，应立即停止重复运行并升级技术处理。
  
  ### 旧区域结算
  
  历史上各大区存在多套独立统计和结算。当前统一结算已覆盖 ARAB、PHL、SASIA 和 AFRICA，但旧任务可能仍为兼容、历史补跑或特定业务线保留。
  同一大区、同一精确周期不得同时使用旧结算和统一结算。是否启用必须以当前调度配置和发布记录为准，不能只看代码或旧文档名称。
  
  ## 当前与旧版判断表
  
  | 场景        | 当前应使用             | 旧版处理             |
  | --------- | ----------------- | ---------------- |
  | 新增公会数据需求  | 新版日/周期数据和统一汇总     | 只维护存量兼容          |
  | 公会基础成员流程  | 现行公会成员和邀请流程       | 旧邀请列表仅兼容展示与处理    |
  | 外管成员和公会归属 | ACM V3            | 不使用旧 BD 身份和旧关系设计 |
  | 外管数据看板    | ACM V3 多政策看板      | 旧页面跳转或保留数据中心壳    |
  | 多区结算      | 目标区当前统一或明确独立结算    | 禁止新旧同周期并行        |
  | BD 区域历史对账 | 现存后台报表            | 不恢复旧用户中心         |
  | ALFA      | ALFA 独立数据、结算和月度工资 | 不套用 Hoki 默认政策    |
  
  ## 业务规则
+ 先判断应用，再判断大区，最后判断角色、权限和周期。
+ Hoki 与 ALFA 的同名大区可以使用不同政策。
+ 当前归属用于当前经营，冻结归属用于历史周期。
+ 新需求优先使用统一数据、ACM V3 和现行结算能力。
+ 存量 BD 报表可以保留，但不再作为新用户体系扩展。
+ 旧页面存在不等于旧业务仍是权威口径。
+ 同周期新旧结算不得同时运行。
  
  ## 常见问题
  
  ### 为什么同为 ARAB，Hoki 和 ALFA 工资不同
  
  两者是独立业务线，配置和工资政策不同。ALFA AR 还有月度分层工资，不能用 Hoki 半月政策解释。
  
  ### 为什么 PHL 有的页面按周，有的按半月
  
  PHL 的工资和报表周期允许按当前配置选择，存量 BD 与 ACM 报表中仍存在半月口径。比较前必须确认具体页面和起止日。
  
  ### MENA 有看板，为什么没有统一结算结果
  
  数据展示能力和正式结算能力是两个开关。MENA 当前已进入统一数据范围，但未纳入统一正式结算范围。
  
  ### 旧 BD 页面文件还存在，为什么说入口已退役
  
  部分页面用于兼容跳转或保留数据中心展示。权威成员、归属、权限和看板已迁移到 ACM V3。
  
  ### ACM 转移公会后，为什么历史月份仍属于原成员
  
  历史月份读取冻结归属，设计目的就是防止当前转移改写历史工资。
  
  ### 为什么存量 BD 报表与 ACM V3 看板数量不同
  
  先核对周期、大区、实时归属或冻结归属、快照刷新时间，以及报表是否过滤跨区或无效账号。两者用途和刷新链路不同，不能只按总数判断错误。
