# 等级榜单荣誉与公会活动

最后核验日期：2026-08-19

## 适用人群

面向负责公会成长体系、榜单、荣誉资源、奖励活动、铭牌和公会 PK 的产品与活动运营人员。

## 功能说明

公会成长体验由五类能力组成：业绩等级、等级资源、铭牌、荣誉、榜单与活动。它们彼此有关，但不是同一份状态。运营配置或排查时必须先确认问题属于哪一类。

## 公会等级

### 等级如何产生

当前周期有效业绩会匹配所在大区的等级政策，得到当前等级和下一等级目标。周期结束后，系统根据完整周期结果进行评级，并更新公会后续展示所需的等级状态。
等级政策由运营配置，通常包含：

+ 各等级所需业绩。
+ 等级展示名称。
+ 头像框、主页背景、主页徽章。
+ 升级弹窗背景和头像资源。
  手册不固化具体门槛。产品验收或运营排查时，以目标大区当前生效配置和目标周期绑定配置为准。
  
  ### 当前等级与历史等级
+ 当前等级：用于经营进度和主页展示，可能随当前周期业绩变化。
+ 周期评级：周期结束后按完整结果评定，用于周期结果、升级通知和适用资源。
+ 历史榜单中的等级：属于当期快照，不应被当前配置反向改写。
  
  ### 等级资源
  
  等级资源可以分别用于头像、公会主页、徽章和升级弹窗。资源缺失时，等级数值仍可能正确；这属于配置或素材问题，不应通过修改业绩修复。
  
  ## 升级通知
  
  达到纳入升级通知范围的高等级公会，会在周期汇总和评级完成后收到升级消息。通知按大区、公会和周期防重复，只记录同一周期已经发送的最高等级。
  发送前提：
1. 目标大区有生效等级配置。
2. 目标周期汇总已经成功，且包含等级所需指标。
3. 周期评级已完成。
4. 目标等级属于通知范围。
   重复运行不会向同一公会重复发送同等级通知。若公会在同周期再次升到更高等级，可按最高等级规则处理。
   
   ## 铭牌与勋章
   
   铭牌用于公会名称或相关场景的等级展示，有独立的等级和有效期。它与公会业绩等级相关，但保存和生效方式不同。
   
   | 概念                                                                       | 主要来源          | 主要用途           |
   | ------------------------------------------------------------------------ | ------------- | -------------- |
   | 业绩等级                                                                     | 周期业绩和等级政策     | 经营进度、等级资源、升级通知 |
   | 铭牌等级                                                                     | 自动评级更新或后台人工维护 | 名称区域和指定页面展示    |
   | 荣誉                                                                       | 榜单或活动结果       | 荣誉墙、履历和历史成就    |
   | 后台可以查询当前生效铭牌并调整等级或有效期。人工调整可能覆盖自动结果，因此操作前要确认当前周期评级是否正在运行，以及调整是临时补偿还是长期口径。 |               |                |
   
   ## 公会荣誉
   
   ### 荣誉资源
   
   运营后台维护荣誉名称、多语言文案、墙面、徽章和动画等资源。荣誉资源可以复用于多个公会的历史成就。
   
   ### 荣誉获得与展示
   
   最强公会等活动在周期结束后为符合名次的公会写入荣誉。公会主页展示最近荣誉，完整荣誉页按年份分组展示历史记录。
   同一公会、同一荣誉、同一月份不会重复沉淀。荣誉属于历史事实，后续修改公会名称、成员或等级不应删除已获得荣誉。
   
   ### 荣誉与个人证书
   
   公会荣誉和个人证书都可能出现在荣耀履历中，但主体不同。个人证书不能直接解释为公会荣誉；如需设计公会证书，应单独定义获得主体、资源和展示入口。
   
   ## 最强公会
   
   ### 当前周期榜
   
   活动页展示当前周期业绩前 99 名公会，同时返回当前用户所在公会的名次、等级、成员数和周期结束时间。
   为保护经营数据：
+ 其他公会的具体业绩可能隐藏。
+ 当前用户所在公会可看到自身业绩。
+ 排名仍可展示，隐藏数值不影响名次计算。
  
  ### 奖励列表
  
  活动展示前三名奖励。奖励内容来自目标大区当前生效的奖励包配置，运营更换奖励包后页面内容随配置变化。
  配置缺失时，奖励列表可能为空。上线活动前应同时核对三个名次的奖励内容和素材，而不是只检查榜单页面。
  
  ### 历史前三
  
  历史页按周期展示前三名公会。历史记录保留当期名次和等级信息；公会名称和头像可能优先展示当前资料，因此视觉资料与当期快照可能存在差异。
  
  ### 周期结束处理
  
  周期结束后，系统会根据上一周期结果：
1. 固化前三名。
2. 为对应公会增加荣誉。
3. 保存当期等级与公会展示信息。
4. 按大区奖励配置向公会长发放奖励。
5. 标记奖励结果，防止重复发放。
   若榜单有结果但荣誉或奖励缺失，应分别检查荣誉配置、奖励配置和发放状态，不能只重算排行榜。
   
   ## 公会 PK
   
   ### 用户端能力
   
   公会 PK 提供：
+ 查看当月赛事。
+ 判断当前用户或公会是否能报名。
+ 公会报名。
+ 查看全部赛段。
+ 查看某赛段的参赛公会和对阵。
+ 查看赛段排名。
+ 查看最终前三名比赛结果。
  报名通常由具备公会管理资格的用户操作。是否可报名由赛事时间、公会状态、是否已经报名和赛事规则共同决定。
  
  ### 赛段
  
  赛事可从资格阶段逐步进入淘汰赛、半决赛、决赛及季军赛。每个赛段有自己的开始结束时间、参赛范围、对阵和处理状态。
  产品设计和运营执行必须区分：
+ 赛事已创建但未开始。
+ 当前处于报名期。
+ 某赛段正在进行。
+ 赛段等待成绩录入或处理。
+ 赛事已经结束。
  
  ### 运营后台能力
  
  运营可以：
1. 创建赛事并维护基础信息。
2. 配置或调整全部赛段。
3. 开始赛事。
4. 查看赛段参赛公会和对阵。
5. 填写或修正比赛分数。
6. 处理赛段晋级结果。
7. 查看最终排名和活动结果。
   
   ### 后台自动处理
   
   赛事期间会自动处理当前赛事状态、统计结果，并在适用节点发送开始或参与消息。自动处理不能替代运营对赛段时间和成绩的核对。
   
   ### PK 高风险操作
   
   | 操作   | 风险          | 必须确认           |
   | ---- | ----------- | -------------- |
   | 开始赛事 | 可能锁定报名并进入赛程 | 赛段时间、参赛名单、规则   |
   | 调整赛段 | 可能影响已生成对阵   | 赛事是否已开始、是否已有成绩 |
   | 提交分数 | 影响排名和晋级     | 对阵、公会、分数证据     |
   | 处理晋级 | 生成下一阶段参赛方   | 当前阶段成绩是否全部确认   |
   
   ## 适用范围
   
   | 能力                                                        | 适用说明                                 |
   | --------------------------------------------------------- | ------------------------------------ |
   | 公会等级                                                      | 目标大区存在完整等级政策时可用                      |
   | 等级资源                                                      | 随等级政策配置，可因大区而不同                      |
   | 升级通知                                                      | 只处理已开放通知的等级和大区                       |
   | 铭牌                                                        | 支持自动更新和后台人工维护                        |
   | 荣誉                                                        | 需要荣誉资源和对应活动结果                        |
   | 最强公会                                                      | 需要榜单、等级、荣誉和奖励配置共同就绪；历史上主要从 ARAB 主线演进 |
   | 公会 PK                                                     | 以当前应用和运营排期是否开放赛事为准                   |
   | 不要因为某大区有公会数据，就默认它已经开放最强公会、荣誉或 PK。活动上线应逐项验收入口、数据、配置、任务和奖励。 |                                      |
   
   ## 业务规则
+ 等级、铭牌和荣誉是三个独立状态，不能互相替代。
+ 当前周期等级会变化，历史等级和荣誉按当期结果保留。
+ 排行数据隐藏只影响展示，不影响真实名次。
+ 活动奖励按目标大区当前有效配置读取，配置变更要走活动验收。
+ 同一周期的升级通知、荣誉和奖励必须防重复。
+ PK 成绩和晋级必须按赛段顺序处理，不能跳过未确认阶段。
+ 人工调整资源或有效期前，应确认是否会与自动处理互相覆盖。
  
  ## 常见问题
  
  ### 公会业绩已达标，为什么等级没更新
  
  先确认页面展示的是当前进度还是周期评级，再检查数据刷新、等级配置和目标周期评级是否完成。
  
  ### 等级正确但头像框或背景为空
  
  优先检查该等级的资源配置和素材可用性，不要修改业绩数据。
  
  ### 铭牌等级和主页等级不一样
  
  铭牌有独立有效期，并可能被后台人工调整。核对最近评级时间和人工修改记录。
  
  ### 最强公会有名次但没有奖励
  
  分别检查奖励包是否完整、周期结果是否已固化、发放是否失败以及公会长状态。不要重复发放前先确认是否已有成功记录。
  
  ### 荣誉页没有最新名次
  
  当前榜单不等于历史荣誉。只有周期结束后的荣誉沉淀完成，荣誉页才会出现。
  
  ### PK 排名未进入下一阶段
  
  检查当前赛段是否结束、所有对阵是否有有效成绩，以及运营是否已经处理赛段晋级。
