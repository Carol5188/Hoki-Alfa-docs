# 数据看板与指标口径

最后核验日期：2026-08-19

## 适用人群

面向设计或解释公会数据页面、处理数据咨询、使用后台报表和导出的产品、数据运营、日常运营与财务运营人员。

## 功能说明

现行公会数据能力覆盖公会和主播两个主体，并提供日数据、周期数据、历史查询、成员排行、支持者、业绩明细、礼物明细和上麦记录。页面会根据公会所在大区选择默认指标和结算周期。

## 时间与周期

### 统一业务时区

公会日界线、周期边界和结算日期统一按 UTC+3 理解。用户手机显示的本地日期可能不同，处理跨时区投诉时应先转换到 UTC+3。

### 日期查询规则

| 查询类型                                          | 日期含义         | 返回范围           |
| --------------------------------------------- | ------------ | -------------- |
| 日数据                                           | 指定 UTC+3 自然日 | 当日完整或当前已统计数据   |
| 周期数据                                          | 周期内任意一天      | 自动定位该日所属周、半月或月 |
| 当前周期                                          | 不指定历史日期      | 周期开始日至当前业务日    |
| 历史周期                                          | 指定已结束周期内日期   | 周期完整开始日至结束日    |
| 未来日期不可查询。日期格式错误或选择未来业务日时，页面应提示用户调整日期，而不是展示零值。 |              |                |

### 周期类型

| 周期                                | 常见用途                     | 边界说明                    |
| --------------------------------- | ------------------------ | ----------------------- |
| 日                                 | 日常数据、日榜和刷新观察             | UTC+3 当天                |
| 周                                 | 部分大区工资或经营统计              | 由大区有效配置决定；统一周结算链路按周日至周六 |
| 半月                                | 多数钻石业绩大区的工资与结算           | 每月上半月和下半月               |
| 月                                 | TR、CIS 宝石口径及 ALFA 月度层级工资 | UTC+3 自然月               |
| 不要只凭页面名称猜周期。应以页面显示的起止日期和大区当前配置为准。 |                          |                         |

## 数据展示模板

公会所在大区会指定默认展示模板。模板决定页面优先呈现什么，但不代表其他业务事实不存在。
| 模板 | 主要含义 |
| --- | --- |
| 等级 | 以当前有效业绩、等级、下一等级目标和等级资源为重点 |
| 业绩 | 以大区政策计算后的有效业绩为重点 |
| 钻石收益 | 以原始礼物钻石和相关收益为重点 |
| 红钻/宝石 | 以即时和次日结算的宝石类指标及折算价值为重点 |

## 公会数据

### 公会日数据

| 指标                                              | 业务口径                         |
| ----------------------------------------------- | ---------------------------- |
| 今日业绩                                            | 该公会在目标业务日产生的有效业绩             |
| 业绩环比                                            | 今日业绩相对前一业务日的变化；昨日为零或无数据时不计算  |
| 活跃主播数                                           | 目标日有效业绩大于零的去重主播数             |
| 全部成员数                                           | 当前公会长、管理员和普通成员总数             |
| 活跃率                                             | 活跃主播数占当前全部成员数的比例             |
| 活跃变化                                            | 今日活跃主播数相对昨日活跃主播数的变化；昨日为零时不计算 |
| 送礼人数                                            | 当日向公会内主播送出有效礼物的去重用户数         |
| 活跃率使用当前成员总数作为分母，而活跃变化直接比较今日与昨日的活跃主播数。两者不是同一个概念。 |                              |

### 公会周期数据

| 指标   | 业务口径                     |
| ---- | ------------------------ |
| 周期业绩 | 周期开始日至统计截止日的有效业绩         |
| 业绩环比 | 当前进度相对可比上一周期的变化          |
| 送礼人数 | 周期内有效支持者去重数              |
| 新增主播 | 周期内成功加入公会的去重主播数          |
| 公会工资 | 成功工资快照中的公会工资；没有成功快照时为空   |
| 工资环比 | 当前与上一可比周期工资的变化；上一期为零时不计算 |

### 当前等级数据

当前业绩页同时展示周期起止日、当前有效业绩、等级、下一等级目标和等级资源。最高等级没有下一档时，页面应显示“已达最高等级”而不是把特殊占位值展示给用户。
部分当前业绩页面还会展示按大区配置的奖励档位，包括每档目标、奖励内容和当前达成状态。奖励档位与公会等级不是同一概念；页面没有档位时，应先确认目标大区是否配置和启用，不应套用其他大区的奖励数值。

## 主播数据

### 主播日数据

| 指标     | 业务口径                   |
| ------ | ---------------------- |
| 今日业绩   | 主播目标日有效业绩              |
| 业绩环比   | 相对前一业务日变化；昨日为零或无数据时不计算 |
| 礼物钻石   | 主播目标日收到的原始有效礼物钻石       |
| 礼物钻石环比 | 相对昨日原始礼物钻石的变化          |
| 支持者数   | 当日给该主播送礼的去重用户数         |
| 上麦时长   | 当日有效上麦分钟数              |
| 上麦达标   | 当日是否达到所在政策的有效上麦标准      |

### 主播周期数据

主播周期页提供周期业绩、礼物钻石、支持者、上麦分钟、有效上麦天数，以及适用时的预支工资开关、已预支次数和已预支金额。
当前周期环比按“同进度”比较。例如当前周期进行到第 5 天，应与上一周期前 5 天比较，不能拿不完整当前周期和完整上一周期直接比较。

### 主播周期总览

适用的工资政策会返回：

+ 主播业绩工资。
+ 钻石余额工资。
+ 该主播为公会产生的工资。
+ 当前工资档位和下一档目标。
+ 即时宝石、次日宝石及其折算价值。
  某项不适用于当前大区或没有对应工资政策时应显示为空或不展示，不能当作零工资。
  
  ## 上麦数据
  
  主播可以查看周期内每天的上麦时长和达标状态，也可以查看指定月份的达标日历。有效上麦标准由当前业务政策决定；历史页面中常见的固定时长只是当时政策，不应作为跨区永久规则。
  上麦数据通常先形成日记录，再汇总为周期总时长和有效天数，因此当天数据与周期汇总可能存在短暂刷新差。
  
  ## 排行榜与数据显隐
  
  ### 公会内排行
  
  支持公会主播日榜和周期榜，也支持公会支持者日榜。排行通常按有效业绩降序，同值时使用稳定顺序，分页切换不会改变已经确定的先后关系。
  公会长可在设置中控制普通查看者是否看到榜单具体业绩：
+ 开启：榜单展示正常数值。
+ 关闭：普通查看者只能看到自己的具体数值，其他成员显示隐藏状态。
+ 公会长：仍可查看完整数值。
  
  ### 跨公会排行
  
  公会业绩榜和最强公会榜会展示名次、公会资料和当前公会位置。为保护经营数据，非本人公会的具体业绩可能被隐藏；部分榜单只展示当前公会附近名次的数值。
  因此，“看得到名次但看不到分数”是设计行为，不应当作数据丢失。
  
  ## 支持者与明细
  
  登录用户可以在允许的页面中查看公会或主播的支持者列表、业绩明细和礼物钻石明细，并可按日或周期查询历史。
  
  | 能力                                                                            | 含义                                                  |
  | ----------------------------------------------------------------------------- | --------------------------------------------------- |
  | 支持者列表                                                                         | 对目标公会或主播产生有效礼物贡献的用户                                 |
  | 主播最新送礼记录                                                                      | 展示该主播最近收到的有效礼物及送礼用户，用于观察近期支持行为；它是滚动记录，不等同于完整日榜或周期汇总 |
  | 新增主播                                                                          | 目标周期内成功加入公会的主播                                      |
  | 业绩明细                                                                          | 按业务来源聚合后的有效业绩明细                                     |
  | 礼物钻石明细                                                                        | 固定按原始有效礼物钻石查看，不跟随默认业绩模板切换                           |
  | 这些属于敏感横向数据访问，会记录查询情况。运营对外解释或导出时，应遵守数据权限和隐私要求。                                 |                                                     |
  | 最新送礼记录与汇总数据的用途不同：前者用于查看近期事件，后者用于核对某日或某周期总量。受统计刷新、礼物有效性和展示条数限制影响，两者不能逐条简单相加比较。 |                                                     |
  
  ## 数据刷新时间
  
  部分公会和主播数据页会展示“数据更新于”。它表示目标数据最近一次成功统计完成的时间，不是用户打开页面的时间，也不是客户端本地时间。
  需要注意：
+ 同一份缓存数据在有效期内反复打开，刷新时间保持不变。
+ 没有可用成功批次时，页面可能使用当前时间作为展示兜底，不能仅凭时间判断统计完整。
+ 排行和部分明细页不一定提供刷新时间，应结合目标周期和后台运行记录判断。
  
  ## 运营后台报表
  
  ### 公会和主播汇总报表
  
  运营可按有权限的大区、周期、日期、公会或主播筛选报表，并查看汇总、明细和导出。统一报表用于跨大区采用一致的页面结构，但指标可用性仍受大区政策控制。
  
  ### 主播个人看板
  
  个人看板支持按主播或公会查询：
+ 按主播：左侧展示主播身份、个人指标和适用工资，右侧展示周期结束日所属公会的经营指标。
+ 按公会：主播区域为空，直接展示公会指标、支持者和公会内主播排名。
  后台可以按大区配置可见字段。被隐藏或不适用的字段为空；真实业务结果为零时返回零，两者必须在产品展示上区分。
  
  ### 导出
  
  导出应使用与页面相同的筛选、大区、周期和数据权限。异步导出成功只代表文件生成完成，不代表报表已经完成业务结算。
  
  ## 数据状态解释
  
  | 页面状态  | 含义               | 处理方式         |
  | ----- | ---------------- | ------------ |
  | 零值    | 该指标适用且结果确实为零     | 正常展示零        |
  | 空值    | 指标不适用、被隐藏或缺少有效数据 | 查看大区、配置和快照状态 |
  | 预估    | 当前周期按现有数据计算      | 提醒结果仍会变化     |
  | 已结算   | 读取成功结算结果         | 作为正式业务结果     |
  | 无数据   | 目标主体、周期或成功统计不存在  | 核对筛选和统计运行情况  |
  | 数据更新中 | 后台正在重新汇总或缓存尚未刷新  | 等待完成后再次核对    |
  
  ## 业务规则
+ 日、周期和历史数据均使用 UTC+3。
+ 当前周期只统计到当前业务日，历史周期使用完整边界。
+ 有效业绩与原始礼物钻石是不同指标，除非大区政策明确一致。
+ 环比的上一期为零或无数据时不应显示无穷大或误导性百分比。
+ 空值不能自动转换为零，预估值不能标记为已结算。
+ 用户端、后台页面和导出应使用相同主体、周期和大区筛选后再比较。
+ 历史查询优先使用当时完成或冻结的数据，不因当前成员归属变化而重写。
  
  ## 常见问题
  
  ### 为什么今天的数据比用户本地账单少一天
  
  先检查用户本地时区与 UTC+3 的日期差，再确认当天统计是否完成。
  
  ### 为什么周期环比和整期同比对不上
  
  当前周期使用同进度比较，历史完整周期才使用完整范围比较。
  
  ### 为什么业绩和礼物钻石不一致
  
  业绩经过大区政策计算，礼物钻石表示原始有效礼物价值。两者用途不同。
  
  ### 为什么活跃率变化和活跃率环比看起来不一致
  
  当前活跃率以当前成员数为分母；活跃变化比较今日与昨日活跃主播数，不重复使用成员数分母。
  
  ### 为什么后台看得到零，用户端却不展示
  
  先判断该字段在用户端是否适用、是否被配置隐藏、是否有成功快照。后台真实零值和用户端空态不能直接等同。
  
  ### 为什么导出与页面数量不同
  
  核对导出发起时的筛选、数据范围、周期和生成时间。归属或数据在导出期间变化，也可能导致当前页面与旧导出不同。
