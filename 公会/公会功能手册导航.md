# 公会功能手册导航

最后核验日期：2026-08-19

## 适用人群

这套手册面向新入职的产品、日常运营、数据运营、活动运营、财务运营和 ACM 管理人员。它回答的是“系统有哪些公会能力、谁可以使用、业务结果是什么、异常时先看什么”，不用于指导研发实现或系统部署。
历史页面和少量旧文案可能使用“工会”。本手册统一使用“公会”，两者指同一业务对象。

## 功能说明

本手册以当前用户端、公会 H5、运营后台和 ACM V3 的实际可用能力为主线，覆盖公会创建与成员关系、数据指标、工资结算、等级活动、后台操作以及大区和业务线差异。只在第 07 篇集中说明仍需兼容的旧页面、存量报表和已经退役的入口。

## 使用方法

1. 第一次接触公会业务，先阅读[公会业务全景与角色生命周期](https://guangzhouhoki.yuque.com/mameam/znfgci/fnppgq805itxdu2w)。
2. 处理用户咨询、入会或成员问题，阅读[用户端与成员管理](https://guangzhouhoki.yuque.com/mameam/znfgci/ocu6y9k89qzmlqb5/edit?toc_node_uuid=GC8W5DS_QxDjV2W_)。
3. 解释数据、排行或统计差异，阅读[数据看板与指标口径](03-数据看板与指标口径.md)。
4. 处理工资、预支或结算问题，阅读[业绩工资与结算](04-业绩工资与结算.md)。
5. 策划等级、榜单、荣誉或 PK，阅读[等级榜单荣誉与公会活动](05-等级榜单荣誉与公会活动.md)。
6. 在运营后台执行操作，阅读[运营后台操作手册](06-运营后台操作手册.md)。
7. 遇到大区、ALFA、ACM V3、BD 或旧页面差异，阅读[大区业务线与新旧版本差异](07-大区业务线与新旧版本差异.md)。

   ## 术语速查
   
   | 术语                           | 业务含义                                           |
   | ---------------------------- | ---------------------------------------------- |
   | Hoki                         | 当前公会主线所在的应用和业务线                                |
   | ALFA                         | 与 Hoki 并行、拥有独立数据和工资政策的应用和业务线                   |
   | H5                           | 在应用内打开的网页功能页；本手册中的公会 H5 主要承载数据、管理和 ACM 工作台能力   |
   | 公会                           | 由公会长负责、包含管理员和主播成员的运营组织                         |
   | 公会长                          | 公会负责人，拥有公会内最高管理权限                              |
   | 公会管理员                        | 由公会长任命，可按授权管理成员数据、资料或邀请                        |
   | 主播                           | 以成员身份加入公会并产生公会相关数据的用户                          |
   | BD                           | 负责公会拓展和归属的业务角色；在现行体系中通常作为 ACM 层级角色出现           |
   | ACM                          | 外管层级体系，管理成员账号、公会归属、权限、额度和周期数据                  |
   | ACM V3                       | 当前使用的第三版 ACM 体系，也是现行外管成员、归属和数据看板的权威入口          |
   | PK                           | 公会之间按活动规则进行的对抗赛                                |
   | V1/V2                        | 第一版、第二版功能或页面的版本标记；现行与旧版关系见第 07 篇               |
   | UTC+3                        | 比协调世界时早 3 小时的业务时区，公会业务日和周期边界以此划分               |
   | AR / ARAB                    | 同一运营大区的简称和完整代码；ALFA 的“AR 月度工资”即 ALFA ARAB 月度工资 |
   | PHL、SASIA、AFRICA、MENA、TR、CIS | 其他运营大区代码；各区能力和口径见第 07 篇                        |
   | 运营大区                         | 决定功能开关、指标、周期、工资政策和报表范围的业务分区                    |
   | 业务日                          | 按 UTC+3 划分的自然日，不等同于用户手机本地日期                    |
   | 结算周期                         | 日、周、半月或月等统计与工资核算范围                             |
   | 当前周期                         | 正在进行中的周期，数据通常统计到当前业务日                          |
   | 历史周期                         | 已结束的完整周期，原则上使用冻结或已完成数据                         |
   | 业绩                           | 按所在大区政策计算的有效贡献，不一定等于原始礼物钻石                     |
   | 快照                           | 某一时间点固定下来的工资、归属或统计结果，用于追溯和防止历史漂移               |
   | 预估                           | 周期尚未完成时依据当前数据计算的参考结果，不代表正式发放                   |
   | 已结算                          | 正式结算成功后形成的结果，优先于预估值展示                          |
   
   ## 业务规则
+ 功能是否可见，先看业务线、大区、角色和权限，再看数据是否已生成。
+ 相同名称的指标在不同大区可能使用不同有效业绩口径，不能直接跨区比较。
+ 当前周期会继续变化，历史周期应以已完成或冻结结果为准。
+ 配置中的门槛、比例和奖励可能调整，本手册不固化具体数值；操作时以后台当前有效配置为准。
+ 页面显示为空不一定是故障，可能是功能不适用、没有成功快照、没有权限或尚未到统计时间。
+ 正文只写现行能力；旧入口、兼容页面和退役链路统一在第 07 篇说明。
  
  ## 常见问题
  
  ### 应该以手册、页面还是历史操作记录为准
  
  先以当前页面可见入口和目标大区的有效规则为准，再用本手册理解业务含义。历史操作记录用于追溯当时结果，不能代替当前规则。
  
  ### 页面名称与手册用词不一致怎么办
  
  先确认是否为旧客户端、兼容页面或历史“工会”文案。若功能行为也有差异，按第 07 篇的新旧版本说明判断，不把旧入口当作当前标准。
  
  ### 手册为什么不写固定门槛、比例和奖励数量
  
  这些内容会随大区和运营配置调整。处理具体业务时，应查看后台当前有效版本及其生效时间。
