# ACM 功能手册导航

最后核验日期：2026-08-19

## 适用人群

本手册面向新入职的产品、日常运营、数据运营、财务运营、区域负责人和 ACM 管理人员。它用于回答“ACM 当前有哪些能力、谁能使用、数据怎么算、组织调整会影响什么、异常时先查哪里”，不用于指导研发、部署或数据修复。
ACM 是平台用于管理外部拓展成员、团队层级、公会归属、操作权限、业务额度和周期数据的体系。部分历史材料将 ACM 成员统称为 BD；在现行 ACM V3 中，BD 更适合作为某一层级或职责角色理解，不能与整套 ACM 体系画等号。

## 功能说明

本手册以 ACM V3 当前工作台、运营后台和报表页面的实际行为为准，覆盖：

1. ACM 团队、成员、层级与公会归属。
2. 用户端工作台的日常业务操作。
3. 运营后台的账号、模板、权限、额度和团队治理。
4. 公会业绩、人员规模、工资和历史周期数据。
5. 半月、月度统计快照及不同大区的工资口径。
6. 报表、导出、异常记录和新旧版本迁移状态。
   旧 BD 入口、兼容报表和已退役能力只在第 07 篇说明，不作为当前操作入口推荐。

    ## 核心关系图解
    
    | 对象     | 业务含义                   | 关键边界                        |
    | ------ | ---------------------- | --------------------------- |
    | 根 ACM  | 一支 ACM 团队的最高层账号        | 一支团队只能归属于一个根结构，根账号可有多名运营负责人 |
    | ACM 成员 | 根 ACM 之下的外部拓展或管理成员     | 所在层级、可创建下级类型和能力均受模板约束       |
    | 直属成员   | 当前账号下一层直接管理的成员         | 直属成员的数据可以按其完整下级团队汇总展示       |
    | 公会     | 由某个 ACM 成员直接负责拓展和归属的公会 | 当前归属可以调整，已冻结周期的历史归属不随之改写    |
    | 运营负责人  | 平台侧负责该根团队的运营人员         | 决定后台管理和报表可见范围，不等于工资归属人      |
    | 团队模板   | 定义层级、上下级关系、默认权限和默认额度   | 模板变更可能影响整支团队，需先预览影响         |
    
    ## 术语速查
    
    | 术语               | 业务含义                                     |
    | ---------------- | ---------------------------------------- |
    | ACM              | 外部拓展团队的成员、层级、公会归属、权限、额度和数据管理体系           |
    | ACM V3           | 当前生效的第三版 ACM 体系，是现行团队关系和数据归属的权威来源        |
    | BD               | 公会拓展角色的常用称呼；在当前体系中通常是某一层级或职责，而不是独立系统     |
    | H5               | 在应用内打开的网页工作台；本手册中的 H5 指 ACM 用户端页面，不是运营后台 |
    | UID              | 用户的稳定身份编号，用于把 ACM 后台账号与正确的用户端身份绑定        |
    | 根 ACM            | 一支团队层级树的最上级账号，也称根账号                      |
    | 外部成员             | 纳入 ACM 团队、承担拓展或管理职责的业务成员                 |
    | 层级               | 成员在团队模板中的位置；层级名称和可管理关系可由模板定义             |
    | 直属               | 与当前账号只相隔一层的成员或直接归属公会                     |
    | 下级团队             | 当前账号之下的全部层级成员及其公会，不只包括直属成员               |
    | 自营范围             | 直接归属于当前账号的公会范围                           |
    | 团队范围             | 当前账号自营公会加全部下级成员公会的范围                     |
    | 公会归属             | 某个公会当前由哪名 ACM 成员直接负责                     |
    | 运营负责人            | 在平台后台负责某支 ACM 团队的运营人员，可一人负责多队，也可多人负责一队   |
    | 模板               | 一套团队层级、关系、默认权限和额度规则                      |
    | 功能权限             | 决定一个账号能否执行某项业务动作                         |
    | 数据范围             | 决定一个账号能看自己、下级团队还是更大范围的数据                 |
    | 额度               | 团队在指定周期内可执行某类业务动作的数量限制                   |
    | 周期快照             | 将某个周期的归属、统计和工资结果固定下来，供历史查询和核对            |
    | 当前周期             | 尚未结束的半月或月份，结果会随业务数据变化，通常为预估值             |
    | 历史周期             | 已结束并完成统计的周期，结果原则上保持冻结                    |
    | UTC+3            | 比协调世界时早 3 小时的业务时区，统计日和周期边界以此划分           |
    | Hoki             | 公会主业务线之一，ACM 数据按大区适用不同统计政策               |
    | ALFA             | 与 Hoki 并行的业务线，当前 ACM 重点覆盖 ARAB 月度分层工资    |
    | AR / ARAB        | 同一运营大区的简称与完整称呼                           |
    | PHL、SASIA、TR、CIS | 当前 ACM 报表中具有特定统计模式的运营大区                  |
    
    ## 业务规则
+ 先判断账号属于哪支团队和哪个层级，再判断它有什么功能权限和数据范围。
+ 功能权限、数据范围、后台管理范围和报表范围是四个不同概念，不能相互替代。
+ 当前组织关系用于当前周期；历史周期优先使用当时冻结的公会和成员归属。
+ 同名指标可能因业务线、大区和政策不同而采用不同口径，禁止直接跨区比较工资。
+ 当前周期结果可刷新，历史周期结果只有在满足严格条件并留痕后才能修复。
+ 门槛、比例、固定奖励和额度由有效政策或模板决定，本手册不固化易变数值。
  
  ## 常见问题
  
  ### ACM、BD 和运营负责人是不是同一个角色
  
  不是。ACM 是整套团队管理体系；BD 通常指其中承担公会拓展职责的成员；运营负责人是平台后台侧的管理人员。三者可能有关联，但权限、数据范围和工资归属不同。
  
  ### 为什么同一个人能管理团队，却看不到全量报表
  
  后台管理范围和报表全局范围独立控制。能操作一支团队，只说明拥有该团队的管理关系，不代表拥有跨团队或全局报表权限。
  
  ### 公会转给新成员后，过去周期的工资会跟着转吗
  
  不会。当前归属从转移生效后变化，已经冻结的历史归属和工资保持原结果，避免历史账目漂移。
  
  ### 为什么手册不列出固定比例、额度或奖励金额
  
  这些值可能按大区、模板和生效时间调整。实际处理时应查看后台当前有效政策、模板或额度规则。
