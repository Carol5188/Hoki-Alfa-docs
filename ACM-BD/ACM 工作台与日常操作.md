## ACM 工作台与日常操作

最后核验日期：2026-08-19

## 适用人群

本篇面向使用 ACM V3 用户端工作台的根 ACM、外部成员、BD 和负责解答工作台问题的运营人员。重点说明当前可见入口、日常操作、前置条件、操作结果和常见失败原因。

## 功能说明

ACM V3 工作台分为成员数据入口和管理工具入口。成员数据入口用于查看团队、成员、公会和周期数据；管理工具入口用于添加成员、创建公会、搜索用户以及执行获授权的业务动作。
页面以账号最终权限动态展示工具。没有显示某项功能时，不应通过历史链接判断功能仍然开放，应先核对入口权限、账号状态、团队模板和所在大区。

## 工作台首页

工作台通常聚合以下信息：
| 区域 | 展示内容 | 说明 |
| --- | --- | --- |
| 身份信息 | 当前 ACM 身份、团队或层级 | 层级名称以团队模板为准 |
| 快捷工具 | 添加成员、创建公会、用户搜索及其他获授权工具 | 只显示最终有效权限 |
| 团队概览 | 当前成员、公会或数据入口 | 展示范围取决于账号身份和数据权限 |
| 额度提示 | 受限动作的可用情况 | 额度由根团队共享，页面值可能随团队其他成员操作变化 |

### 入口不可见排查

1. 确认用户端 UID 是否正确绑定到有效 ACM 账号。
2. 确认账号处于启用状态并仍在有效团队关系中。
3. 分别检查成员工作台入口和 ACM 管理工作台入口权限。
4. 检查目标工具是否在模板默认权限或账号个别权限中有效。
5. 检查当前客户端是否仍在使用已经退役的旧 BD 路径。
   
   ## 成员与公会视图
   
   ### 当前成员
   
   | 视图                                        | 主要内容            | 业务用途                |
   | ----------------------------------------- | --------------- | ------------------- |
   | 当前成员                                      | 当前团队关系中可见的成员    | 查看现有团队结构和成员状态       |
   | 直属成员                                      | 当前账号下一层的成员      | 进入直属成员完整团队数据或开展日常跟进 |
   | 成员历史                                      | 与当前账号或团队有关的历史关系 | 追溯加入、转移或退出后的关系变化    |
   | 当前可见成员以现行团队关系为准。成员历史用于追溯，不代表该成员当前仍由查看者管理。 |                 |                     |
   
   ### 当前公会与公会历史
   
   | 视图     | 归属依据          | 注意事项             |
   | ------ | ------------- | ---------------- |
   | 当前公会   | 当前直接归属和当前团队结构 | 转移后会显示在新归属人的当前范围 |
   | 公会历史   | 过去形成并保留的归属记录  | 只用于追溯，不应当作当前管理权限 |
   | 周期公会数据 | 该周期冻结或当期使用的归属 | 历史周期不会随当前公会转移而改变 |
   
   ## 添加外部成员
   
   ### 适用角色
   
   拥有“添加外部成员”权限，且模板允许创建相应下级的 ACM 账号。
   
   ### 前置条件
+ 当前账号启用并处于有效团队中。
+ 目标用户符合成为 ACM 成员的身份要求。
+ 目标用户未被其他 ACM 关系占用。
+ 目标层级处于启用状态，且允许由当前层级创建。
+ 团队共享额度有剩余，或该动作当前不设额度。
  
  ### 操作流程
1. 进入添加成员页面并查找目标用户。
2. 核对用户 UID、昵称、区域等身份信息，防止同名误操作。
3. 选择当前账号可创建的目标层级。
4. 查看页面给出的资格和额度结果。
5. 确认后提交，成功后返回成员列表核对关系。
   
   ### 操作结果
   
   成功后，目标用户成为当前账号的直属成员，并继承其层级对应的模板规则。目标用户是否立即看到成员数据入口和管理工具，取决于最终入口与功能权限。
   
   ### 常见失败原因
   
   | 现象                                                              | 常见原因              | 处理建议               |
   | --------------------------------------------------------------- | ----------------- | ------------------ |
   | 找到用户但不可添加                                                       | 用户已属于其他 ACM 关系    | 核实当前归属，不要重复创建      |
   | 没有可选层级                                                          | 模板未允许当前层级创建下级     | 联系后台运营核对模板关系       |
   | 提示额度不足                                                          | 根团队共享额度已用完        | 核对团队当期用量和有效额度规则    |
   | 提交后关系未建立                                                        | 提交时账号或用户状态已变化     | 刷新页面后重新核对，不要连续重复提交 |
   | 新成员没有工作台                                                        | UID 未正确绑定或入口权限未生效 | 核对绑定、账号状态和两类入口权限   |
   | 现行 H5 明确提供添加成员能力。成员转移、删除和复杂层级调整应在运营后台执行，不应将历史页面或非现行入口当作用户端标准能力。 |                   |                    |
   
   ## 创建公会
   
   ### 适用角色
   
   拥有“创建公会”权限的 ACM 账号。
   
   ### 前置条件
+ 目标用户具备创建公会的业务资格。
+ 目标用户当前未被不兼容的公会或 ACM 关系占用。
+ 当前账号、团队、业务线和大区状态有效。
+ 团队共享建会额度有剩余，或该动作当前不设额度。
+ 团队模板明确本次建会采用直接完成或用户确认方式。
  
  ### 两种建会结果
  
  | 模式   | 提交后的结果                | 运营跟进                 |
  | ---- | --------------------- | -------------------- |
  | 直接创建 | 资格校验通过后直接建立公会和当前归属    | 返回当前公会列表核对           |
  | 用户确认 | 先向目标用户发起确认，用户接受后才完成创建 | 跟进确认状态，未确认前不要按建会成功统计 |
  
  ### 常见失败原因
+ 目标用户不满足当前公会创建条件。
+ 用户已有冲突的公会身份或待处理建会关系。
+ 当前账号无建会权限或已被停用。
+ 根团队共享额度不足。
+ 用户所在区域与目标业务要求不一致。
+ 用户确认模式下，邀请被拒绝、过期或尚未处理。
  
  ## 用户搜索与可执行动作
  
  用户搜索是多个业务动作的起点。搜索结果应展示可用于核对身份的信息，并按当前账号权限和目标用户状态给出可执行动作。
  
  | 动作                                                      | 适用角色         | 前置条件            | 成功结果          | 常见失败原因            |
  | ------------------------------------------------------- | ------------ | --------------- | ------------- | ----------------- |
  | 查看用户                                                    | 有用户搜索权限的 ACM | 目标用户存在且在可查询范围   | 展示允许查看的信息     | 输入不准确、用户不存在或范围受限  |
  | 编辑用户信息                                                  | 有编辑权限的 ACM   | 目标字段允许修改        | 用户资料按规则更新     | 字段不允许、内容校验失败或状态变化 |
  | 封禁用户                                                    | 有封禁权限的 ACM   | 目标用户符合封禁条件且额度可用 | 形成封禁结果和操作记录   | 目标不可封禁、额度不足或重复操作  |
  | 发放奖励包                                                   | 有奖励权限的 ACM   | 奖励资源有效且用户符合条件   | 奖励发放或进入明确结果状态 | 资源不可用、资格不符或重复发放   |
  | 内容审核                                                    | 有审核权限的 ACM   | 目标内容处于可处理状态     | 记录审核结果        | 内容已处理、状态过期或权限不足   |
  | 投诉处理                                                    | 有投诉权限的 ACM   | 投诉处于可处理范围和状态    | 记录处理结果        | 工单已关闭、已被处理或无权操作   |
  | 搜索到用户只说明用户存在，不代表当前账号对其拥有全部动作。每个动作都要独立检查权限、业务资格、目标状态和额度。 |              |                 |               |                   |
  
  ## 额度在工作台中的含义
  
  当前重点受额度管理的动作包括添加成员、创建公会和封禁用户。额度以根团队为共享单位，同一团队内不同成员的操作会共同消耗可用量。
  
  | 周期类型                                          | 业务含义           | 使用提示             |
  | --------------------------------------------- | -------------- | ---------------- |
  | 按日                                            | 每个业务日重新计算可用量   | 业务日按平台统一时区划分     |
  | 按月                                            | 每个自然业务月重新计算可用量 | 月初重新进入新周期        |
  | 累计                                            | 不按固定周期自动恢复     | 需要后台按规则调整或重置     |
  | 不限                                            | 当前没有有效限制规则     | 不代表动作可以绕过资格和权限校验 |
  | 额度页面是当时查询结果。多人同时操作时，提交阶段仍会再次检查，看到剩余额度不等于预留成功。 |                |                  |
  
  ## 数据中心日常使用
  
  成员数据中心通常提供：
1. 当前周期团队数据汇总。
2. 直接归属公会列表及其指标。
3. 直属成员及其完整下级团队表现。
4. 可选历史周期及冻结结果。
5. 适用大区的业绩、规模和工资指标。
   查看前先确认业务线、大区、周期和范围。同一个账号在不同模式中可能看到不同列；不适用的工资字段不会因为其他大区存在而在当前模式补零展示。
   
   ## 业务规则
+ 页面工具由最终有效权限决定，没有入口时先查权限和账号状态。
+ 添加成员和创建公会都受模板、用户资格、当前关系和团队共享额度约束。
+ 当前 H5 的成员管理重点是查看和添加；复杂结构调整统一由运营后台完成。
+ 公会创建在用户确认模式下，只有确认完成才算成功。
+ 用户搜索、功能权限和目标可操作性必须逐项判断。
+ 当前成员、公会和数据会随关系变化；历史周期按冻结归属解释。
  
  ## 常见问题
  
  ### 为什么根 ACM 也没有某个管理工具
  
  根身份只表示团队层级最高，不等于自动拥有全部功能。应检查管理工作台入口、模板默认权限和账号个别禁止项。
  
  ### 团队明明还有成员额度，为什么仍添加失败
  
  额度只是条件之一。还要检查用户是否已被占用、目标层级是否可创建、父子关系是否合法，以及提交时团队状态是否变化。
  
  ### 建会申请发出后为什么公会列表里没有
  
  如果模板采用用户确认模式，发出确认不等于建会完成。应先查看用户是否已接受以及确认是否仍有效。
  
  ### 为什么工作台能看到历史公会，却不能管理它
  
  历史公会记录用于追溯过去归属。管理权限依据当前归属，转移或退出后的公会不再属于当前管理范围。
  
  ### 为什么历史周期的公会仍显示在原成员名下
  
  这是预期行为。周期关闭后归属被冻结，后续公会转移只影响当前和未来周期。
